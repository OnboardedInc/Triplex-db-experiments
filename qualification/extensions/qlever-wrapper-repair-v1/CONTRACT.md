Tags: `backend:qlever` `problem:wrapper-string-range-numeric-domain`
`mechanism:explicit-wrapper-text-family` `status:source-only`.

This is a reviewable source proposal. No build, SDK/backend call, settings change,
container action or live package integration is granted. The native comparator
[mechanisms memo](../../../wiki/research/qlever-string-comparison-mechanisms-v1.md)
remains source-only. This experiment changes one TypeScript wrapper lowering
branch; the existing QLever binary, main index, writer and caps stay fixed.

[the plan](plan.json). The old WHERE predicate body and its numeric-only ordered
validation remain byte-identical. Numeric boundaries, equality, LIKE and guarded
aggregate fallbacks retain their existing paths. No common expected answer or
language policy is changed.

## Small isolated SDK artifact

Prepare one owned copy of the current QLever package sources/config/public export
map beneath the Q package's ignored experiment area. Apply only the reviewed
compiler branch. Use the ordinary pinned Q package tsdown and declaration
commands, with their configs explicitly adapted only to the owned copy/output.
This is a TypeScript adapter package build, not a QLever native engine build.
Freeze the full declared installed compiler/runtime graph using the reviewed
recursive collector, including actual platform compiler inputs.

Preserve every live source/dist byte. Compare copied source membership/hashes,
complete generated public exports/declarations and all executable modules; only
the reviewed compiler's executable logic may differ. A tiny consumer witness must
use the actual private package's public declarations. Keep existing public Core
and Effect identities through the checked installed dependency layout. No install,
new dependency version or Core generation is included.

Place the worker inside that owned package boundary so its unchanged public QLever
package name resolves by package self-reference. Core/Effect resolve through the
same checked Q package ancestry. Prove the actual resolved facade URL and dependency
identities before any service operation. No module selector, generic ancestor
fallback, generated-dist patch or arbitrary loader is proposed. If ordinary build
or resolution fails, preserve it and stop; a successor needs review.

The build manifest is intentionally not fabricated before its worker/input set is
frozen. Actual runtime manifests follow its anchored generated artifact. Proposed
build reservation is2GiB/2CPU/512MiB disk/300s, sequential child heap768 and outer256.
Those numbers are a proposal, not measured build acceptance.

Datalog payload membership are checked before dependent cases.

After the isolated artifact is anchored, prepare a fresh successor of the original
31-call public extension using that same artifact. Preserve every original logical
ASCII/Unicode expected row, old-cursor/P1/R continuation, correction/history/ACK
assertion, native query text and scoped failure policy. Only owned entry/helper/root
placement and exact artifact binding may change. Use fresh run/scope identities.
Keep the original v6 semantic and formatting failures immutable. New apparatus
identity oracle bytes must match ordinary exclusiveJson serialization; this is an
apparatus-only metadata correction, not a new semantic oracle.

The original mixed-case order, ranges and pagination may still fail after the
family repair. Retain those actual failures. The lowercase repair can qualify only
its explicit end-to-end domain-lowering scope; it cannot qualify general text order,
Unicode policy, the whole public extension or all ten goals. The old20families,

fresh44 claim is bundled into this proposal.

## Stop and review boundaries

Semantic wrong rows retain exact responses and may continue only within the frozen
bounded case inventory. Unknown ACK/ownership/source drift, HTTP/API/cancel failure,
resource breach, wrong basis, payload loss or cleanup uncertainty stops dependent
work without retry or synthetic outcomes. Preserve partial safe files, first
failure, actual settings restoration and process/resource cleanup. No automatic
repair, larger budget, data deletion, restart, copy, fault or recovery is included.

First freeze/review the SDK build worker and exact manifest; execute only after a
separate grant. Then freeze/review actual runtime source, tiny pure/noEmit gates,
artifact/receipt/oracle/profile inputs and canonical manifests. Runtime calls still
need their own exact grant. A distinct verifier must inspect actual semantic rows,
public module consumption, cut/ACK/lineage, controls and complete cleanup before
any scoped acceptance. Native comparator changes remain independently ungranted.
