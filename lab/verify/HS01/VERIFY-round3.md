## Results and reproductions

### 1. Numeric retention — R2-1 closed

`packages/qlever/src/broker/sqlite-worker.ts:330` now maps numeric policies to `{frames:n,bytes:0}`. The independent test in `round3/review.test.ts` runs 0, 1, 2 and Infinity with ACKED at the head, a holder at LSN 7, and ACKED behind the head at LSN 12. It computes the expected prefix separately from the worker and compares the complete numeric/object purge replies. Finite policies progress to exactly that prefix; Infinity keeps everything. The frozen round 2 worker is the negative control: every finite numeric policy stays at anchor 0 while its normalized object policy advances. Thus the test distinguishes the fix from the old behavior.

The six prior independent round 2 tests also pass afresh, unchanged. They exercise the original >16 MiB reproduction against old/new workers, a separate byte/frame suffix oracle, holders and ACKED protection, all compact-id forms and head saturation, a pinned old cut across purge/reopen, CRC anchors, and a typed `FeedRetentionExpired` below the anchor. The original progress fix and its work bound remain intact. The builder suite also exercised the full 268,435,456-byte payload / 268,435,492-byte frame, which purged as one frame and reopened successfully.

### 2. Entity dictionary — collisions do not alias names

`sqlite-worker.ts:156` hashes UTF-16 code units, and line 157 verifies the candidate's stored name in the same lookup. The hash is a lookup key; it is not the identity. My separate BigInt implementation of FNV-1a found 24 collision pairs with a different generator from the builder's. The test appends those names plus empty, embedded-NUL, astral, composed/decomposed Unicode, U+FFFD and distinct lone-surrogate names. It compares ordered whole/entity/id and recent reads against the frozen round 2 worker, repeats after reopen, and appends the names again. No alias, duplicate name allocation, lookup miss or ordering difference occurred. The entity and hash tables have a one-to-one allocation; repeated names reuse it.

The size audit additionally reads both actual 10k OFF databases, independently recomputes every entity's hash, checks duplicate names, distinct referenced eids and colliding-key counts, and compares their table bytes/payloads with dbstat evidence. W0 has 1,900,994 entity names and 288 colliding hash keys. These checks do not infer collision safety merely from the builder's digest.

### 3. INTEGER binding — no observed precision loss

`packages/qlever/src/broker/row-codec.ts:108` binds only integral, non-negative-zero doubles in the half-open int64 range as INTEGER. A double in that range is already an exactly represented integer; converting it to BigInt and back to the driver's nearest double returns that original double. Fractions and values outside int64 retain REAL storage. The `integer` value kind remains a string, preserving all int64 digits.

The independent actual-worker test uses 12,399 values: random IEEE754 bit patterns, signed extreme/subnormal values, NaN/infinities/-0, and adjacent representable doubles around 2^53, 2^62 and 2^63. Each value is stored as both number and datetime; four additional integer strings include both int64 edges and ±9007199254740993. All 24,802 rows match every original own field before and after reopen using strict equality that distinguishes -0 and preserves NaN. Observed classes per numeric kind: 401 compact INTEGER, 11,984 compact REAL, 11 NULL-backed fallback and 3 REAL-backed fallback. Four int64 strings remain TEXT. The fallbacks return the exact original values.
