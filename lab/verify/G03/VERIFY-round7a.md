## Finding F3 — Medium: a rejected control stream skips the new terminal/export path

Location: `lab/bin/ns-run.mjs:141`, before the new catch at line 143 and export at lines 149–160. Related: `lab/bin/box.mjs:135`–139 and `lab/experiments/EXP-G03/ns/smoke.mjs:40`–42.

The coordinator awaits execControl outside a catch. execControl rejects on a failed onControl/handshake, malformed/truncated JSON, timeout or output cap. A rejection therefore leaves runBoxedNS before injector.finish(), trustedTerminal(), observer stop, walker export and capture hashing. The new catch handles only finish() errors after a normally resolved execControl. The smoke caller saves container logs and then calls box.close(), which ordinarily deletes the run volumes; it does not export the raw HR/observer/state files in this failure path. A refusal object, partial stage log and container logs can survive, but the promised raw evidence does not.

Reproduction: `round7a/coordinator-review.mjs` loads the exact reviewed ns-run.mjs and Box.execControl source bytes in VM modules. It substitutes trusted lifecycle/child-stream dependencies, uses the real FaultInjector, and emits a valid before-effect hook through the actual control-pipe handler. The trusted DR model reports checkpoint 1 where the evaluator expects checkpoint 0. The real injector rejects this durability inconsistency with FAULT-POINT-DR-CONTRADICTION. The coordinator exits at stage 9, with zero walker calls, no raw directory, and no ns-terminal/1 record. This does not run a candidate or kernel container on the host. `round7a/coordinator-review.json` records `realBoxExecControl:true`, `realFaultInjector:true`, the valid hook and the contradictory observed/expected checkpoints.

Live positive controls in the same source-bound model demonstrate that status 7, null status, and a failed finish() **do** export six raw files, preserve matching capture digests, construct coordinator-owned terminals, and refuse before parsing deliberately invalid HR JSON. F3 is thus specifically the rejected-promise branch, rather than a missing model export implementation.

Proposed fix: catch execControl rejection into a coordinator-owned failed terminal, retain the cause/partial streams and perform safe stop/proven teardown/export before terminal refusal. If teardown/export cannot be proven safe, explicitly retain the owned forensic volumes and record that gap instead of deleting them. Add a regression through the actual coordinator/execControl path for a rejected hook and for control timeout/truncation; assert raw exports/digests or explicit retained-volume ownership before cleanup. No semantic grant should follow any such failure.

## Finding F4 — Low: an initial null clock domain bypasses the constant-domain check

Location: `lab/bin/ns-run.mjs:22` and 27. The local domain variable uses null as its uninitialized sentinel. When the first authenticated record has domain:null, a different valid domain on the next record is accepted because the comparison is skipped again. The final seal copies the later valid domain, and the initial malformed domain is discarded from the returned poll observations.

Reproduction: independent-review.mjs signs a fresh three-record fixture, changes only the first record's domain to null before signing, and leaves the next poll, final record and seal on the valid boot/zero-offset domain. verifyObserver accepts. The same helper rejects a change between two normal non-null domains, so this exercises the sentinel branch specifically.

The current observer.py always builds a domain object; this is an authenticated malformed-producer fixture, not a way for a candidate without the key to rewrite a captured chain. Its severity is therefore low. It still contradicts the stated invariant that all records have a constant clock domain.

Proposed fix: track initialization separately from the value and validate every record's domain as the expected non-null boot/zero-offset clock object. Add null-first and null-in-all-records controls alongside the normal domain-change control.
