## F7 repair assessment and limits

`Temporal.journalBasis(P)` sets an explicit allValidTime mode and the exact position. `TriplesLive.journalRows` supplies it to transaction, command and feed reads; the shared entity-journal helper gates availability and passes the same P to index and envelope reads. KV's journalScan and index use that basis too. The relevant SQL, SPARQL, KV and adapter visibility paths omit business-time predicates **only** in that mode, preserving recorded-position and retirement visibility. Ordinary public basis resolution constructs its own business-time basis.

[The independent reproduction](round4/journal-clock.ts) uses the actual services/adapters, the prior reviewer's emitted-SQL interpreter on XTDB, the deterministic emitted-SPARQL storage fixture on QLever, and the actual in-memory KV service. It checks nonempty records, complete change bodies, receipt instant/position, command identity, feed order, fixed-P first pages, continuations and an older fixed P after a new commit. [compare-journal.py](round4/compare-journal.py) independently compares their complete logical journal content with the accepted O-REPLAY tree `fed510ecf5137873d5dab1ad192f0e54f8ed0955`. Receipt consistency and observed-answer comparisons are separate checks.

The QLever fixture cannot interpret the entity-journal Datalog join, so positive full entity-page execution there remains **compiler/source evidence**, plus actual positive storage/envelope/command/feed evidence. Its permanent compiler test checks that record and retirement predicates survive while V comparisons disappear; this review also traced the mode through the executor and resolver. No full positive SPARQL entity-index execution or live QLever engine result is claimed. The XTDB interpreter executes emitted SQL and CAS expressions, with its declared dialect adaptations; it does not qualify XTDB's own isolation, planning or durability. Round-B broker paths absent from this checkout remain unqualified.

## Nonblocking findings / open qualification

**N1 — Low, test-control defect: `packages/xtdb/test/journal-clock.test.ts:40`.** The ordinary query control calls `t.entity(subject, {basis:{validAt:900}})` although entity expects the basis directly. The runtime also happens to be 900, so default-time filtering lets the test pass while its explicit input is ignored. Reproduction: inspect the signature and run with runtime 800 plus explicit validAt 1000; the malformed nested argument would read at 800. Proposed fix: use `{validAt:900}` and make explicit V differ from the runtime clock, including both inclusion and exclusion boundaries. This is nonblocking for the product repair because the review's correctly shaped, independently checked 55-cut controls pass. No product fix was made here.

**N2 — Medium, repository pack prerequisite outside the RT01 lane: `packages/duckdb/src/effect-storage.ts:112` and `packages/duckdb/src/TypeDomains.ts:17`.** Building the held DuckDB package emits TS4023: exported inferred values use Effect's `NodeInspectSymbol`, which cannot be named. Proposed fix: the package owner should give those exports portable explicit return types and regenerate declarations, then rerun the entire pack/consumer gate.
