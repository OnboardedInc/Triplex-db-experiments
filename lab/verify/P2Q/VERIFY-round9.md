## F1 — major verification gap: inherited/merged public reads escape enumeration

**File/line:** [round8-policy.test.ts:21](tests/round8-policy.test.ts#L21) finds the first interface declaration; line 26 reads only its direct AST members. The fixed route dictionary and `contracts`-derived expected list in the second test do not discover the omitted method either.

**Reproduction:** the scratch copy adds `round9Read` through `TriplesService extends Round9AdditionalReads`, or through a second exported `interface TriplesService` declaration. Its actual implementation is included in `TriplesLive`'s returned service object. The independent control resolves the public type with the TypeScript checker, finds `round9Read`, obtains that function from the actual runtime service and requests **6144** while the broker head is **2048**. It returns **`[]`**, with **zero availability calls and zero mask calls**. Both original enumeration/policy tests pass in each variant. Adding the identical member directly to the original declaration correctly fails inventory; this confirms the actual guard ran and can reject the ordinary addition.

**Impact:** a new public read can bypass both shared policies while this required completeness test reports success. The claim that adding an unreviewed public entry point necessarily fails the guard is false. The method added by these probes is confined to scratch copies; no synthetic read is added to the reviewed product tree.

**Proposed fix:** enumerate resolved service type properties, including heritage and all merged declarations, then require complete classification and dynamic policy cases for that resolved set. Compare exposed runtime service keys where practical, with explicit non-read exemptions. Retain direct, inherited and merged addition controls, and require all three unclassified additions to fail. No guard or product fix was made by this reviewer.
