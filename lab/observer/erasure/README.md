# ER01-S offline erasure scanners

Evaluator-owned code for R38 §4.1 / §6.2, Q82c–d and Q95g. This directory writes no product erasure implementation. It normalizes complete observer file snapshots into **four separate scan results**. A fixture PASS is a statement about those declared synthetic files, never erasure of a running engine or inaccessible physical storage.

- **P:** find a distinct unprotected twin of the same canonical value kind and 32-byte length bucket at each location and phase; search for protected bytes before and after erasure. UTF-8, UTF-16LE, UTF-32LE, JSON escape, base64 and hexadecimal forms are covered. No claim about other encodings, irreversible derived values, native TOAST compression, or Arrow compression follows.
- **C:** get exact envelopes and contexts from the pinned EI evidence; find target and live control before erasure; keep finding the live control afterward. Require ciphertext removal at declared in-place/new-generation locations; permit retention at append-only locations. Physical and decoded vocabulary bytes are both searched; vocabulary positive controls must occur in **decoded words**, not merely codebooks.
- **K:** find each canary wrapped-key version before shredding; search every inventoried key-store file, WAL, heap, TOAST and backup for binary/base64/hex forms. Require wrapped canary bytes absent at shred and rotation and destroyed epoch wrapper bytes absent at rotation. This is deliberately stricter than R38's permission for stale wrapped bytes in non-backup WAL under destroyed epochs. D can PASS such a case while K or the aggregate FAILS. Before D opens, its key inventory must match all K canary versions and controls.
- **D:** a read-only AES-256-GCM decryptor tries all supplied root copies, epoch records, key-store copies and backups. The fixed SQLite fixture record decoder also recovers obsolete key tuples in WAL/free pages, and known before-canary wrappers/epoch boxes are tried wherever physical K scans find them, including Postgres byte fixtures and kms WAL. Before: target **and** live control authenticate to exact expected plaintext digests under their five-part context. Shred/rotate: live control must still open, target must not. A retained usable backup is FAIL; an unreadable/incomplete source, wrong root, blind decoder or failed positive control is REFUSED.

`REFUSED` dominates the aggregate, then `FAIL`, then `PASS`. Individual findings remain visible when another location refuses. Aggregate PASS requires a P/C/K inventory and D; it is limited to `declared-files-only`. Declaring the complete physical inventory is the evaluator's responsibility. Synthetic harness controls are excluded from real engine erasure claims (R38 §4.2, Q56h).

## Raw chunks and ownership

`compile.py case.json /evaluator/normalizer.py` freezes `fsst.py`, `scanners.py`, `decrypt.mjs`, the complete evaluator case, and the exact Node executable path, SHA256 and version into a standalone Python parser. It accepts the existing observer's JSONL raw sample framing on stdin and returns one JSON record object. Python uses only its standard library; AES-GCM uses the separately pinned Node executable and its bundled crypto implementation. A changed or unavailable executable refuses. Parser dependencies cannot be silently selected by bundle bytes or PATH.

The outer frame binds run, stream, source, engine container, case digest and monotonic phase interval. The raw payload binds slot, unique phase nonce, exact inventory paths/location/source-kind/codec, full sizes and SHA256 values, complete/stable-file flags, and the evaluator-pinned EI envelope read. All three phases (`before`, `shred`, `rotate`) are mandatory. Raw bytes are decoded again, never an input verdict. Frames are **not authenticated by these scanners alone**: retain them through OBS01's existing `Bundle`, HMAC chains, external evaluator key and independent host witness. `test_obs_bundle_seal_recomputation` exercises the real Bundle writer and seal verifier, including tampered normalized output. No container is started by these tools.

`snapshot.py` supplies read-only file acquisition for an evaluator observer: every path component uses `O_NOFOLLOW`, regular files only, complete reads with a total budget, pre/post identity/size/mtime/ctime checks, no source SQLite opens. Its caller supplies independently captured EI evidence and passes the resulting raw payload to the existing collector. The file-only helper refuses EI inventory entries: an EI query adapter must acquire those separately. Missing/deleted files currently refuse; a directory deletion needs a separate witnessed directory-inventory adapter, never an invented empty file.

`fixtures.py` deliberately fabricates HO/EI *fixture* frames to test the decoders. Their identity is `offline-fixture-no-engine`, slot `offline`; they are not live collection receipts. Real acquisition of a coherent main DB plus WAL requires a storage snapshot/quiescence witness in addition to each file's stability. The offline fixtures take both while their connection is held; this round does not qualify concurrent production snapshotting.

## Formats and limits

QLever profile `qlever-fsst-squared-le64/0.6` checks the two 2304-byte raw FSST decoder structs per 2^20-word block, both vocabulary copies, internal global ids, compact-vector boundaries, external mmap offsets/footer and internal/external agreement. Escapes, Unicode and external-only words are covered. Unsupported ABI/version/zero-terminated layouts refuse. The decoder is verified against all archive manifest hashes and the real index's known input `provenance/archive/qlever-bootstrap/bootstrap.nt`: it recovers `"1"` and both application IRIs where raw grep misses the literal. The additional planted vocabulary controls use an explicit legal fixture encoder; no new IndexBuilder run or engine was used.

Source format references: [QLever v0.6.0 CompressedVocabulary](https://github.com/ad-freiburg/qlever/blob/v0.6.0/src/index/vocabulary/CompressedVocabulary.h) (FSST-squared, block selection), [FsstCompressor](https://github.com/ad-freiburg/qlever/blob/v0.6.0/src/util/FsstCompressor.h) (raw decoder serialization/reverse decoding), [VocabularyInternalExternal](https://github.com/ad-freiburg/qlever/blob/v0.6.0/src/index/vocabulary/VocabularyInternalExternal.cpp), [FSST struct and escape](https://github.com/cwida/fsst/blob/b228af6356196095eaf9f8f5654b0635f969661e/fsst.h). Implementation is original evaluator code; no upstream source is vendored.

The product key-store schema, envelope AAD encoding and padding are not yet implemented by ER01-C. The D fixture profile makes these choices **explicit rather than assuming a product contract**: `txe1.` uses R38's 16-byte key id / 12-byte nonce / padded ciphertext / 16-byte tag; plaintext padding is uint32-LE length + value + zero fill; AAD is compact JSON of `[tenant, entityId, attribute, assertionId, valueType]`; key wrapping AAD is the key-id hex string; epoch wrapping AAD is compact JSON `[tenant,epoch]`. Every wrapped key/epoch is nonce(12)+ciphertext(32)+tag(16), base64 in records. Root is 32-byte hex. Key sets/authority are `keyset-json/1` and `kms-json/1` records, or actual SQLite with fixture table `er01_keys(key_id,tenant,epoch,wrapped)` plus mandatory WAL. SQLite is replayed on private temporary copies, then read with `mode=ro`; originals are never opened by SQLite. The current view is supplemented by a forensic decoder of the fixed four-column SQLite fixture records anywhere in main/WAL bytes, including deleted tuples. K's known before key/epoch metadata also binds wrappers recovered from physical byte locations. This does not pretend to decode an unknown production schema. Unsupported production schema or Postgres physical key reconstruction refuses. Physical Postgres fixture pages test byte search across boundaries; they are labeled raw-page fixtures, **not native Datomic segment decoding**. D accepts every read-back/extracted key copy supplied in the declared format; native physical extraction remains an adapter to qualify with ER01-C/DA04.

Datomic unknown segment/WAL codecs, JVM/Node heaps, and freed VM/host blocks have explicit REFUSED controls. A planted byte in a mock file cannot qualify an undocumented engine codec or make inaccessible host APFS blocks observable. Their needed changes remain R38's native decoder/EI key path, restarted processes and a disposable VM filesystem/block inventory; host APFS/SSD remapping remains outside the lab proof.

The current O-OBS ERASURE-SCAN semantic schema predates R38's four scans. This normalizer emits `erasure-scans/1`, not a fabricated legacy `keyDestroyedEvidence` boolean. Its record object interoperates with obs-bundle/1 authentication/recomputation. No claim is made that the old semantic oracle accepts the new four-scan schema; that consumer extension and verifier recollection are separate work.

## Offline gates

```sh
node lab/bin/heavy.mjs --label CX-OBS01-ER01-S -- python3 -B lab/observer/erasure/test_scanners.py
node lab/bin/heavy.mjs --label CX-OBS01-ER01-S-retain -- python3 -B lab/observer/erasure/gate.py --output /absolute/new/evaluator/evidence-directory
```

The retained gate saves generated source fixtures, case, exact standalone parsers, raw streams, P/C/K/D records, blind-decoder case, stale-backup finding, codec refusals and SHA256 manifests. All keys are random synthetic controls; no real PII or production secrets are needed. Run the tests under the lab heavy wrapper after checking ≥5 GiB host free space. No Docker or shared resident is used.
