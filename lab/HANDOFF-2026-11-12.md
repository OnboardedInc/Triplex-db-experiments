## What was learned that changes how to work

1. Under `nohlt` a latency verdict is valid only when no agent is doing host-side work; the lock does not cover builds and
   tests. Two agents measuring in one night produced false regressions.
2. The benchmark's old check compared entity, attribute and value only; all "zero violations" before DX-R3 part 4 mean that.
3. The seed failures at 70,000 and 80,000 were gateway heap exhaustion from an unbounded id memo (fixed on the DX-S5 branch).
4. Commit numbers on this test bed are not power-loss durable (the VM disk's sync mode is best-effort).
