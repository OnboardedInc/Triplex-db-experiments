## Changes and coverage

- `broker/snapshot.ts` owns the single availability decision (`awaitSnapshotBasis`) and the single raw-row snapshot representation (`snapshotRows`). The availability function compares the original required cut with the observed cut, waits within its budget, and throws the existing `BasisNotAvailable` carrying required/observed/replica/surface/wait. Broker resolved-prefix waits, actual replica waits, immutable transaction pins and native SPARQL use it. Publication wake-ups, paced marker probes, reset/incarnation brackets and typed transport classification remain separate checks with their existing purposes.
- All broker repository reads merge replica/log/overlay/staged rows first, then call `snapshotRows` before public conversion. Retirement beyond the position or recorded-time cut clears the entire tuple: `retracted_at`, `retracted_position`, `retract_tx_id`. The operation copies rows and retains every other field. An uncommitted negative retirement position is beyond a committed snapshot. Raw `history` explicitly uses the separate lifetime contract and retains the tuple.
- Core `transactionsForEntity` can pass its snapshot into internal exact-position query and receipt callbacks. `TriplesLive` wires that callback directly to `executor.execute` with the original position. Receipt loading uses the same cut through the adapter, including later journal metadata retirement. The journal no longer answers latest then echoes an unavailable snapshot. Existing `ReadError` subclasses propagate by identity, preserving the basis fields. The legacy KV helper caller retains its existing callback; this round qualifies the broker/TriplesLive path, not every backend's future-basis behavior.

The inventory is derived from `StorageAdapterService`, `TriplesService`, `QueryExecutorService`, runtime native facade keys and the explicit `Repository` stub contract. It classifies every member; adding a member without review fails the inventory. Dynamic sentinel tests cover all **24 executable fact/value read entry points**, inside/outside a transaction (48 checks), proving each reaches the common availability function with the original requested position (including explicit cuts distinct from head). All **14 row-returning entry points** must reach the common snapshot representation. Raw history is explicitly checked as lifetime mode; missing and empty inputs remain gated. Query/dependency/native outputs are projected values rather than raw lifetime `TripleRow`s, so they use the shared availability policy and existing basis-filtered compilation/contexts; they have no raw retirement tuple to mask. Full semantic payload regressions cover those supported paths. Trusted authored SPARQL still owns its query semantics; this is not a new arbitrary SPARQL rewriter.

Exemptions are explicit: current-position introspection reports a head/pin without a requested basis; explain methods only compile; mutation/lifecycle/configuration members are not snapshot reads; broker `rawQuery` does not exist; `Repository.at().get/getMany/find/count/timeline` are still explicit EXP-R02 stubs and cannot be certified as working reads. Low-level transport and host-log/feed cursor APIs do not acquire a new snapshot contract. Native facades have their own explicit basis and do not inherit an adapter transaction's ambient pin.

Copied reviewer tests remain byte-identical. They compare full rows, public Triple payloads and cursor/page payloads before/after later commits across overlay, log fallback and replica routes; they cover an old transaction's implicit get pin and full published query/dependency payloads on both clients. New controls cover the entire inventory, staged retirement masking versus raw history, exact future journal fields/wait for present/absent entities, error identity and query-cut binding, and real live journal page byte identity after retirement/replacement.
