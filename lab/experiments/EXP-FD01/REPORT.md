## Result and scope

Built the lane-neutral offline foundation on `exp/FD01-feed-contract`, from main `daeb442226fd50f70323dde0ada5452d93ecfd45`. This is builder evidence, **not NS.P3 closure, a lane promotion or independent verification**. No engines, Docker, live endpoints or engine slots were used. No acceptance files were edited. Nothing was pushed or merged.

Delivered:

- Public core `/feed` contract: source-bound cursors; commit, aborted, epoch and seal resolutions; exact decimal-string coordinates/stamps; per-operation positions, transaction/command IDs and identity-only assert/retract/erase tuples; erasure sequence; nullable pending-RT01 stamps. Canonical bytes reject missing identities, unknown fields and values/envelopes/key IDs.
- Host `/feed` SQLite ConsumerStore: WAL, FULL, fullfsync, checkpoint_fullfsync, disabled auto-checkpoint, 16 MiB journal limit, NORMAL main connection, SQLite >= 3.51.3 checked at open and pragma readback checked. An exclusive SQLite lock on a separate `.lock` file lasts for the writer's lifetime. Effects keyed by (consumer, epoch, position, subject), affected subjects, delivery digests, source frontier and checkpoint commit atomically. Checkpoint CAS fences stale workers; source/stream/order checks and stored digests reject changed re-delivery. Output tables contain identities/coordinates and digests, never fact values.
- Broker adapter and real reader-worker RPC, request kind `feed`. Synchronous `LogFeed.poll` runs inside the worker, not inside Promise.resolve on the server event loop. The adapter accepts commit/abort/epoch/seal input and strips to the contract.
- P2X adapter always requests `exact:true`, maps every tuple ordinal to a logical position, and requires a source-backed asynchronous lookup for the missing assertion/transaction IDs. One P2X operation retains its whole positions/txIds/commandIds group: copying operation-wide command IDs to every ordinal would falsely allocate the same commands new positions. Unknown tuple ordinals are refused. METADATA is never substituted for exact tuples.
- Journal adapter always labelled `A0-control`; no inferred decided stamp. Datomic native adapter explicitly throws `FeedUnavailable`, naming EXP-DF01.
- Public testkit `/feed` audit of an independently enumerated final source prefix, full identity content, commit positions, abort/epoch/seal accounting, per-entity subject order, unique command claims, byte-exact resume, required gap mutation rejection and a reusable 100-crashes-per-hook matrix with a mandatory duplicating split control.
- NS bench JSONL persistence replaced by this SQLite store. Its direct-subject affected set and receipt-clock lag remain explicitly **diagnostic A0**; DI01 and P3M remain responsible for the domain affected set and source-publication clocks. G0 builds, hashes and tests host, and host's alias factory is now actually called, so a clean checkout resolves its SQLite tests through public package aliases.
- Changeset for the public core and testkit subpaths. Host remains private. Only one internal testkit dev dependency was added to host; the final lockfile changes only that workspace link. All prior external resolutions were retained, and the final frozen offline install succeeded.

## Round 2 — QA F1 and F2 (2026-11-09)

North star remains P3 under `lab/SCOPE.md`, `lab/NORTH-STAR.md`, `lab/TARGETS.md` 1.1 P3. This section supersedes the round 1 statements about crash coverage and receipt-clock lag. QA input: `verify/FD01` **fd8f670**, `lab/verify/FD01/VERIFY.md`. Its probes were copied verbatim into `round2/reviewer-probes/`; `ORIGIN.json` verifies every copy against that Git commit. The original mutator is imported unchanged by the concrete crash child and the adapted mutation runner. No engine or acceptance-contract file changed. No dependencies were installed or changed.

**F1 fixed: atomicity is checked before replay, at real commit boundaries.** The existing `SqliteConsumerStore` implementation is unchanged. The reusable suite now takes independent complete before/after `ConsumerSnapshot` expectations and requires each callback to return the durable effects, affected set and checkpoint observed immediately after an abrupt stop, before replay. The concrete driver opens the same SQLite file, reads all three, and audits candidate state before starting the recovery child. State must equal the whole old snapshot before commit and the whole new snapshot after commit. Keyed deduplication after replay cannot conceal a partial durable state.

The child intercepts actual SQLite COMMIT execution, splitting compound `COMMIT; BEGIN IMMEDIATE` statements at their real statement boundaries for crash injection. It adds before-commit and after-commit stops to the original three application hooks. This directly exposes the reviewer's mutation placed **after** the after-effect hook. Method digests and executed commit events are retained. The matrix checks **500 keyed candidate stops, 300 unkeyed split stops and 100 keyed split negative-control stops** (900 total). The keyed split control recovers without gaps or duplicate effects, but its partial pre-replay state must fail atomicity; the unkeyed control must still duplicate at after-effect stops. The suite refuses a void before/after expectation.

The adapted mutation runner also applies the exact QA mutation to the **candidate itself**, then runs the concrete crash test. It requires one specific `Nonatomic consumer state before replay: after-commit` failure, an actual exit 77, exactly one pre-replay observation with both expected effect/affected identities and a null checkpoint, and the before/after events for the first COMMIT. An arbitrary failing test, import error, guessed boolean or error string alone is insufficient. Fresh result: **rejected=true, counterexampleMatches=true, sourceUnchanged=true**; rejection occurs before replay. This is the implementation that previously passed every original test.

**F2 fixed: lag is computed only from per-position source publication.** Core now exports `FeedPosition`, `FeedInstant`, `feedPositionKey` and `publicationLagMs`. The computation accepts a source publication observation and a durable-known observation bound to the same source, stream, epoch, position and host monotonic clock ID. Missing publication, invalid intervals and mismatched bindings are errors. Neither record stamp nor ACK is an input. Testkit's `auditFeedLag` requires coverage of every committed position, rejects duplicate/foreign observations, calculates each interval and rejects a supplied lag that differs.

The actual NS A0 consumer now looks up an independent `publicationOf(key)` observation for every position, validates it **before** committing consumer progress, computes lag at the durable write's completion, and buckets the sample at publication time. ACK lag remains a separate nullable diagnostic; a later ACK never replaces or recomputes publication lag. The QA fixture—publication **100 ms**, durable knowledge **400 ms**, decided stamp numerically **399 ms**—now reports **300 ms**, not 1 ms. The suite rejects a reported 1 ms, a missing publication, and source/clock mismatches. The actual-consumer missing-publication test checks zero samples and no checkpoint advance.

**Integration boundary:** the legacy NS driver has no real lane source-publication observer integrated yet. It now refuses those P3 samples instead of falling back to `receipt.instant` or ACK arrival. P3M must supply the actual lane publication map through `publicationOf`; the offline seam and falsifier are implemented here. No live-lane publication, reader load, O-DOMAIN affected set, native erase/excision/restore or end-to-end P3 result is claimed.
