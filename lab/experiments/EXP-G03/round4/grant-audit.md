# Q93a grant-path inventory (proposal only)

Scope: merged gate.mjs and claim.mjs, plus receipt.mjs because gate delegates its final verdict to it. A status **consumer** is included even when another module produced the status. Boolean prerequisite predicates, hashes and successful process exits are not standalone semantic grants; their role is recorded below. No centralization is implemented in this round. Q93a itself applies to seed reuse; this is the requested application of its principle to qualification.

`Run` uses a random exclusive raw directory and append-only receipt; `engineGate` binds owner/container ID/start time, image/config, endpoint, built packages and run-end hashes. These are common refusal guards, not content admission. The following routes feed `counts`/reasons into `verdictOf`:

| NS `gateNS` (482–563) | Counts executions/correctness; stores bar PASS fields; may temporarily obtain receipt PASS | Fresh driver report, endpoint, frozen generator/trace/seed/composition/oracle bindings and invalidity checks. | `receipt.verdictOf` (74–87), assigned in gate (740–742) | PASS or PASS_SUBSET if no reasons, required fields and nonzero executions | Content: **presence/count checks, not semantic recomputation**. CLI printing of PASS and language/status tallies only mirror the paths above. Preflight success, kill proof, slot ownership, readiness, image/build/store hashes, warm-up and process exits should be **refusal-only**. Their content checks include exact expected probe tuples, a positive connectivity control, denied destinations/DNS, matching container identity, and host cgroup visibility with candidate cgroup absent. Their freshness/binding comes from the current named candidate/probe and authority/runtime config. These checks establish isolation conditions, not correct database answers.

## Proposed single grant

There are more than a few grant surfaces. Introduce one final, evaluator-owned `admitExecutedAttempt` in a future reviewed change. Only it can construct the outer QUALIFIED/PASS receipt (one private constructor). It would open one immutable attempt bundle, resolve the full authority/evaluator/source identities, recompute all required expected/observed bytes against authority-pinned case selection, check complete candidate/A0/mode coverage and paired measurements, and bind those results to the attempt nonce and exact endpoint/slot configuration. Legacy G0/G1/G2/G4/GS adapters would produce typed observations and refusals; document/core/comparator APIs would return diagnostics/results without an admission label. Offline data could be compared but could never satisfy the registered-slot input.

Isolation/preflight/kill, owner/readiness/resource/process/timing checks would append refusals only. Removing a refusal would not create positive content evidence. The single final check would run after immutable evidence sealing and final cleanup and refuse on missing, stale, altered, cross-attempt or unbound objects. It would have explicit tests for the currently separate core/document/status routes and for `counts.fail` without a reason. Keep per-case comparator results as internal values; success on one case cannot grant an attempt. This proposal is **not implemented or verified** here.

## This round's evidence writers (rule 9a)

- `round4/replay-evidence.mjs`: rechecks every object hash and the 64 retained case-result/2 comparisons for each positive bundle; asserts schema, exact offline refusal codes, empty remaining resources and cgroupGone on each recorded removal. Content is rejudged bytes. Freshness is the captured current request/result, protected evaluator commit and holder; binding is the request's exact authority/source IDs plus evaluator/source bundles and case input/instance identities. Its output records counts/identities; it cannot grant production qualification.
- `round4/cleanup-audit.mjs`: requires successful current engine inventory commands, exact empty container/network/new-volume sets, exactly the declared retained round-2 store, no own ledger reservations and no named protected clones. Content is inventory equality, freshness is new successful reads with observedAt, binding is the two recorded fixture holders plus known CLI holder and source-snapshot hash. It writes cleanup facts, never a semantic PASS.
- `source-snapshot.json`, `fixture-provenance.json`, `bundle-binding.json` and final evidence manifest: SHA-256 actual source/evidence bytes, compare executing evaluator copies with worktree bytes, retain exact Git bundles and confirm positive request authority/source commits exist in fetched bundle objects. Fresh attempt directories/requests distinguish this round; full commit IDs, bundle hashes and per-file hashes bind observations. `preimagesRetained: true` means object existence was actually checked, not that any workload qualified.
- TAP result statements: only terminal summary plus command exit status counts as a passing suite, with explicit denominator, zero skips/cancellations/todo and saved exact source hashes. The retained failed contract verify remains a failure. No earlier round's TAP or qualification label is reused as this round's result.

- `containedFixtures.q` optional `TX2_FIXTURE_TRACE` writer: retains the exact current request and parsed protected-driver output under this attempt's random fixture ID and request sequence, after checking child exit success. It records the evaluator's result without relabelling it, enabling diagnosis of pre-core refusals; it adds no grant. IDs in the request bind source, authority, evaluator, holder, store and fresh work paths.

Actual attempt-two disk-floor refusals demonstrate the distinction: core QUALIFIED appeared with only 46/53 cases because later A0 prerequisite work was interrupted; the outer qualifier remained DIAGNOSTIC with isolation/evaluator refusals and released resources. Never consume that inner label as final admission. A final single grant must check complete A0 coverage as well as candidate coverage and final isolation.

`attempt3/disk-observations.jsonl` records new statvfs free-byte reads, timestamps and the attempt's source-snapshot hash. These are host-filesystem diagnostics, not slot/input semantic evidence; no gate decision reads this diagnostic file. Actual engine admission independently reads free space and can only refuse at its floor. Interrupted attempts remain failed, including when another request from the same suite passed cleanly.
