## Observed refinements during implementation

- X2 is reachable and returns HTTP 200 with plaintext `Alive.`, not Prometheus. Its explicit decoder retains that exact body.
- Native PostgreSQL BOOL OID 16 uses `t`/`f`; the decoder now uses the wire type, never coerces ordinary text `t`.
- `xt.source_log_msgs` requires message-ID bounds. The final collector uses the exact current `latestProcessedMsgId` solely as a point-query position, not as a mutation counter.
- `xt.block_files` and `xt.table_block_files` require bounds, but **R30 Q4, sections 4.1–4.2** documents a worse constraint: GC can remove even a just-listed file and the missing-file loader can hang. On this live shared resident those file-backed queries are not safely collectable without a stable clone/snapshot or an engine loader fix. No such change was made. The final collector stops that gap, records file inventory, and uses readable `xt.live_tables` and `xt.trie_stats` catalog snapshots instead. Initial rejected unbounded queries and their engine error bytes are retained; no missing block was queried.
- `xt.txs` joined on the own marker's `_system_from = system_time` is reachable and returns one committed native transaction. Both marker content and position must match before/after the disposable client crash. This closes the position-binding gap for that client-crash case, not an engine-restart case.
- Access through `/proc/1/root/etc/xtdb/*` is denied with the existing observer capabilities. Changing capabilities or adding read-only engine-config mounts would be needed for that path. It was not changed; process identity, current native endpoints and host container configuration remain readable.
