# EXP-SQL01 round 2 — temporal route equivalence and checkpoint isolation

Builder CX-SQL01, branch `exp/SQL01-broker-sqlite`. Requested review fixes are implemented in `7c65e2fc` and `14f1e12a341ab1b54e89b8e891f953544a17ef1b`; final gate results follow below. This remains a default-off experimental broker, subject to independent review.

## Changes

**F1:** On replica outage, `BrokerStorageAdapter` now bypasses the position-only H1 whenever the resolved request includes `recordedAt`. The indexed complete source (`recent_rows`, through `fromLogAsync`) retains retracted rows below H and applies the existing combined record-time, position and valid-time predicates. Filtering an H1 result afterward cannot restore a discarded row, so that alternative was rejected. Position-only cuts retain H1 and its existing horizon rule. No timestamp-aware H1 retention claim is made.

Copied `review.test.ts`, `schedules.test.ts`, `gate.mjs`, `vitest.config.ts`, `kill.mjs` and `kill-child.ts` from the read-only reviewer tree. [Origin hashes](../../verify/SQL01/evidence/round2-regression-origins.json) identify the reviewer bytes; the tests have additive regressions. The reviewer's exact combined-cut test failed 30 versus 40 on the starting implementation, with unchanged source during execution: [receipt](../../verify/SQL01/evidence/r2-before-temporal.json), [failure](../../verify/SQL01/evidence/r2-before-temporal.log), [rows](../../verify/SQL01/evidence/r2-before-temporal-recorded-cut.json). Its fixture remains locally under the receipt's data path.

Added 37 request shapes (omitted basis, valid-time boundaries, position-only, time-only, and their combinations). Each identical request is compared by exact IDs with the complete-source predicate on the reachable overlay route, the outage route before purge, and the outage route after advancing H. Named historical positions fall below H on the last route; omitted positions still resolve to the current head. This establishes 111 route/cut comparisons, rather than interpreting a changed basis as equivalent.

**F2:** The append/ACK path no longer gates readers or calls a steady-state checkpoint. Every 25 frames it checks WAL size and, above 64 MiB, sets one shared atomic maintenance-request flag. The separate checkpointer polls that flag every 100 ms and runs periodic maintenance every four seconds. PASSIVE remains the normal policy. The backstop closes the reader gate on the maintenance thread, allows up to 20 ms for existing pool reads, and skips the attempt if a reader remains. It runs PASSIVE first; incomplete copying (including a separate stuck reader) skips RESTART. RESTART uses `busy_timeout=0`, so it never waits on a reader while holding SQLite's writer lock. Every path opens the reader gate in `finally`.

A separate connection alone was insufficient: a waiting RESTART can itself hold SQLite's writer lock. This is why the maintenance connection uses nonwaiting lock acquisition, in addition to moving the gate away from append. Normal checkpoint I/O and CPU contention can still affect commit latency; this is not a claim of zero performance interference.

`checkpointStatus()` exposes cumulative outcome counts and the last 128 timestamped attempts, with duration and SQLite busy/log/checkpointed counters; `checkpoint()` explicitly requests backstop maintenance for diagnostics. Outcomes include complete, incomplete, busy, readers-busy and error. The held-reader regression records an incomplete attempt while the reader pins its actual marker snapshot, then a successful RESTART after release. All commits finish before releasing that reader. WAL can exceed 64 MiB while a reader is stuck; 64 MiB is a trigger, not a hard bound, and no reader eviction policy was added.

The first full concurrency run on `7c65e2fc` found a real new interaction: the deferred append transaction read the marker before acquiring its write lock, so concurrent RESTART could produce an immediate SQLite lock-upgrade failure. [First failure](../../verify/SQL01/evidence/r2-final-review.log) is retained, with its [source-bound receipt](../../verify/SQL01/evidence/r2-final-review.json). Both append and read-modify-write purge now use `BEGIN IMMEDIATE` through better-sqlite3's transaction wrapper. A deterministic regression pauses the actual writer algorithm after its marker read and uses a test-only nonwaiting write-lock probe on another worker: the probe succeeds before append, fails with SQLITE_BUSY while append is paused, and maintenance succeeds after append completes. This distinguishes a reserved write lock from a mere read snapshot. Instrumented worker hashes and checkpoint outcomes are retained with the test result.

## Limits and operations

The review's deterministic temporal 30/40 defect is fixed by routing. The original assertion-only 30/40 observation in the initial report remains unexplained: that schedule had no later retraction, and F1 does not establish its cause. The copied hot-subject test retains a complete first-failure fixture if a future exact-row mismatch occurs.

SIGKILL tests leave host/device caches alive. No power cut, VFS durability-fault injection, new WAL-corruption run, 80-stop rerun, full root check, package packing, external consumer effect/checkpoint crash matrix, P1 acceptance at 64/256/1024 clients, year-one scale, erasure qualification or production promotion was performed in round 2. The 50-stop schedule is the requested narrower durability check. Existing high-fanout worker request listeners still emit MaxListenersExceededWarning during overlap; this round does not change their lifecycle. Performance timings under shared lab load are diagnostic, not calibrated TARGETS acceptance.

No subagent, engine lifecycle action, exclusive slot, main-checkout edit, unrelated database/port, merge, push, deployment or publication was used. Live requests use only qlever-dev at port 7070 and uniquely named graphs. Gates/builds run through `lab/bin/heavy.mjs`; admission disk observations stayed above 5 GiB. Original and first-failure evidence is retained; synthetic raw database fixtures remain in gitignored `lab/verify/SQL01/data/` and `runs/` paths. No manual fixture cleanup was performed.

Open work: independent verification of this final head; investigation if the assertion-only case recurs; calibrated checkpoint/reader-level latency and WAL-growth policy under indefinitely stuck readers; physical power-loss qualification. Record-time-aware H1 is a future optimization; exact record-time reads currently use the complete indexed source.
