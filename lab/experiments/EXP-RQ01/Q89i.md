# EXP-RQ01 round 2 contract pin

North star: P1 immutable named snapshots and P4 exact route admission. Goals and targets:

Q89i, read from the main checkout's `lab/acceptance/RULINGS-PENDING.md` for this round:

> Every read at a named basis returns the snapshot as known at that basis: a retirement (retraction, deletion) recorded after the cut is invisible, including its metadata, so repeating the request after later commits returns identical bytes (HE-5). Raw-lifetime rows (a row with its whole later history, O-REPLAY AMB-01 A) are a separate history API with its own result contract and are compared separately; the route-equivalence harness names which contract each driver serves and never compares one against the other.

Snapshot rows mask `retracted_at`, `retracted_position`, and `retract_tx_id` together
when the retirement is beyond either the position or record-time cut. Retirements
inside the cut retain all metadata. History requests with the snapshot contract
include retracted rows with metadata as of the cut. Raw-lifetime requests retain
full metadata, are checked against the raw reference, and do not assert HE-5.

The actual XTDB offline client's physical result is explicitly named raw-lifetime;
its product adapter has not been changed to implement an immutable snapshot view.
