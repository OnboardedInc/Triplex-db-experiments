# Integrated account evidence

The manifest paths are relative to the durable `evidence/DX-THIN1/int1` directory. Run `shasum -a 256 -c SHA256SUMS` there with the manifest from this branch.

| Directory or files | What to inspect |
| --- | --- |
| `proof-b`, `proof-c` | Fresh native thin and deep scopes, full metadata from original command receipts, independent Python replay, release evaluations, durable page readbacks and 23 publication schedules. The second proof interposes a genuine write after capture and runs the sender’s independent receipt worker and the ordinary deep activation. |
| `idle-c`, `thin-c` | Two-slot SQL stack. Compare one and eight idle scopes. For the wide case compare the same 1,000 already-read people before and after adding 98,000 untouched people. Check the second 1% on its first real reads after import. |
| `idle-h`, `deep-h` | One ordinary exclusive slot with two independent gateway JVMs. Eight idle scopes and 10,000 deep people were measured separately. The 9,800 new cold people were counted in the ledger at both measured reader watermarks. |
| `moving-*.json` | Guest process memory over two traversals of 48,000 distinct eight-fact subjects at a fixed receipt. Pair A kept a synthetic microtask chain alive. Pairs B and C yield to the event loop before GC so discarded weak references can be collected. Pair C also binds the executed binaries, sources, guest boot and attempt. |
| `thin-b`, `deep-c`, `checks` | First failed observation and first failed dense import, package and focused test logs, frozen input and source-tree checks, controller validation and manager release records. |

Each population census takes a measurement after seeding the 2% cohort and reading half. It adds the 98% cold cohort, waits for the live feed watermark and repeats the measurement at the same set of admitted people. The reported marginal RSS is the signed difference divided by those new people. The reader charge counts packed bytes, keys and an entry allowance. The separate gateway counters cover their ID memos and parsed entities. PostgreSQL process RSS can count shared pages multiple times. Per-idle-scope values are the difference between one and eight unqueried scopes divided by seven.

The two physical placement cases use 90 accounts with 100 people and ten with 2,000. Every person has the same account-local original values and a disjoint public ID range in both arms. Each import writes SCALE1’s subject account key, catalog, directory and paged membership rows. The verifier reads the complete roster from the physical gateway and reconciles it to the original assertion receipts. The fixed 2% activity schedule measures priority 7. Each native arm checks stored per-person state. The final comparison recomputes the ordered rosters, original tenant seed digests, individual selector and transaction receipts and logical work outputs for all 100 accounts. The absolute release positions may differ between the physical placements.

The normal SCALE1 runner accepts `DX_INT1_READERS=touched` and optionally `DX_INT1_DEEP_RELEASE=ead90`. Its ordinary release keeps the frozen edits. In touched mode the runner consumes the actual seed journal into a durable policy index during import and reports its time and disk cost. Cold, certified deep people supply policy inputs from disk. Changes to an owned entity send that person's world to the exact source at the release cut. Full independent verification reads the original world separately after publication.
