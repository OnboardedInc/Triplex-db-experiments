# Compact Datomic save

**North star.** P2 durable per-save latency, with P1/P3 exact cuts and feed, P4 current pulls, and P5 activation at the same source basis. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

## Source records

Every account has a unique source key and epoch. Every placement, location, and jurisdiction has a subject entity keyed by its account and root ID. Placement children live in their placement's event chain. A subject and its account each carry one cardinality-one head reference. Head history stays enabled. Subject revision is the position of its head event, with zero for a new subject.

| Datom on a save event | Index or interpretation |
| --- | --- |
| `:compact/command` | Unique value of account and caller command ID. The receipt uses this ID, the feed key, recorded clock, and the asserting Datomic transaction read from its datom. |
| `:compact/position` | Unique value of account and 16-digit ordinal. An ordered AVET range reads a page without looking at other accounts. The transactor allocates one successor for each successful member. |
| `:compact/subject-ref` | Reference to the owner. The owner key survives subject retirement and remains searchable for history and erasure. |
| `:compact/previous` | Reference to the owner's previous event, omitted for its first save. Incremental current reads stop at their immutable cached head. |
| `:compact/recorded` | Server-assigned integer microseconds. The serial function uses the larger of its clock and the preceding account clock plus one. Physical `:db/txInstant` supplies native metadata. |
| `:compact/body` | Unindexed versioned array with the command fingerprint, typed assertions and retired assertion coordinates. Entity suffixes resolve under the owner. Attribute codes resolve through the versioned W0 dictionary. Validity uses exact UTC microsecond strings and half-open bounds. |

A fresh assertion ID is the account position and its assertion ordinal. A replacement is an explicit retirement plus an assertion. A partial retroactive correction retires the original and asserts the kept slices and the correction with their explicit valid-time bounds. Readers reconstruct assert and retire record times and feed deltas from the two event coordinates. Cross-account references are out of the experiment's schema. A migration can carry original IDs in a versioned side table.

## Write, receipt and reads

- A trusted gateway prepares and validates the command at one immutable subject revision. The installed transaction function verifies the expected head and the command claim against the transactor's predecessor. A group tracks its evolving account and subject heads in a single invocation. It serializes successful members in offer order within an account. Stale members consume no position. The transaction reports individual receipts after the native future completes and the original request fingerprint is verified. A lost response resolves through the claim and reads the original position, time and native transaction.
- An account cut is `(account, epoch, position)`. Position zero is empty. A record-time cut maps to the largest committed position whose clock is at or before it by binary search of the dense position index. For an explicit position, read the event's native transaction, select `d/as-of`, and walk past later subject heads inside that same native transaction. Replay at or before the logical cut. One immutable database value and one account position bind every hop in a world read.
- Current reads cache only touched subjects' live interval facts, keyed by the immutable subject head. Apply new events between that head and the captured head, retaining future-valid intervals. A miss rebuilds just that subject and referenced shared roots. Pinned reads use the native historical path, folding past events at the cut. A bounded independently receipted checkpoint could cap long-tail replay later. Current readers use an authoritative head or sync to one before answering.
- Each feed entry reconstructs the asserted and retired IDs, owner or child, attribute and valid interval. Retirements retrieve the original envelope by its account position. Physical Datomic transactions with no logical member consume no feed position. Durable consumer checkpoints retain the account epoch and position. Shared-root effects still require W0's reverse-reference dependency projection.
- For subject retirement, emit explicit fact retirements or a typed retirement marker with the same exact expansion. Preserve assertion history. For erasure, protect only the PII scalar with an independent per-person AEAD key; keep its attribute, identity and intervals readable. Persist the erase fence and timestamp against the same owner, then destroy that key before acknowledging success. Every view consults the current fence even at an old cut. Do not cache decrypted values or store plaintext or a plaintext digest in Datomic, logs, derived channels or backups. Exact protected resends reuse the original sealed request bytes. The key authority must keep deletion tombstones outside source backups, survive process restarts and prove deletion across its copies. A gateway-local key authority can exercise the protocol on synthetic values, with production key custody and restore evidence still required. [Datomic excision limits](https://docs.datomic.com/operation/excision.html)
- Activation and notices bind an account predecessor, epoch, valid instant, release bytes and hash, previous notice tail, census, interpreter and selection version in the event body. The proposed concrete mode adds cardinality-many `:compact/output-chunk` and `:compact/notice-chunk` on that event in the same native transaction. Each unindexed value carries a chunk ordinal and actual typed records. The event body binds the expected counts and chunk hash. A normal edit with no owed work adds no notice record. A notice-relevant edit adds its atomic recipe or actual debt and posting delta. The receiver keeps exact per-item sequences, pending payload and cursor in its own transaction. A recipe prices recoverable debt only. The one-second stored-output gate also requires actual changed outputs and notice records before ACK. The prototype exercises the activation marker and predecessor. [Activation join](https://github.com/OnboardedInc/Triplex-db-experiments/blob/9904c54d7/lab/experiments/EXP-DX1/actv-lazy/JOIN.md) · [Datomic transaction functions](https://docs.datomic.com/transactions/transaction-functions.html)

For an existing subject and account, solo writes six event datoms, two subject-head datoms, two account-head datoms, and one transaction instant. In a group of `k` successful saves touching `a` existing accounts and distinct established subjects the count is `8k + 2a + 1`. The 1-, 3- and 25-fact saves each have this same shape. The body size varies with values and intervals. [Measured byte census](CENSUS.md)

Empty saves can advance an account without a business mutation. Unsuccessful members leave no logical event. Native scans now see event envelopes. Typed range, dependency, cursor and user-query indexes need exact projections at explicitly bound cuts. Datomic Pro peer credentials address the full database. A pooled deployment still needs a proved storage-layer account boundary under TARGETS before qualifying.
