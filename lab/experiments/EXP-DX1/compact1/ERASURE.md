# Protected values and identity-only erase events

**North star.** P1 old cuts, P2 receipts, P3 ordered journal and the erasure requirement. [Scope](../../../SCOPE.md) · [Priorities](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

An authorized peer stages one AES-GCM envelope using the W0 SSN key family scoped to account, placement, attribute and generation. The authentication data also binds the opaque version ID, entity and both valid-time endpoints. The ordinary native save stores the envelope in one unindexed attribute on a separate entity. Its unique index key is the account and opaque random version ID. The body, stored journal, checkpoint and feed use that identity. The claim digest binds the safe identity, and an exact resend compares the original authenticated envelope bytes at their storage location. Neither a plaintext digest nor an encrypted copy goes into a query key. Authorized world reads can resolve the envelope after checking the current frontier.

An ordinary protected replacement adds two datoms for its new version ID and its envelope. It makes the same one synchronous native append as an ordinary write. Preparing and verifying the sealed input is peer work. The transactor checks the subject revision, current key generation and version uniqueness. The simple one-SSN W0 schema uses one revocable generation per placement. Multiple protected field families or individually erasable assertions need explicit selectors and independently managed keys.

An erase computes the epoch's exact protected assertion identities from the owner's immutable predecessor chain, including retired assertions. The native append records the revocation, new generation and identity-only journal. Before success, the peer writes the independent ledger and removes the old in-process keys. A failed mirror can resume from the original command receipt. A repeat uses the original marker timestamp, and a new command that matches nothing writes an empty journal. A new authorized assertion has a fresh generation and ID. Erase identity enumeration still grows with the owner's protected history.

Reader operations capture the current source and independent ledger views lazily on the first protected value, even for a cached or pinned business cut. Erased data becomes the original typed marker before unsealing. A read without a usable authority or key fails before exposing protected bytes. Raw SQL/Datomic readings can see opaque IDs and encrypted envelopes, and need the erasure-aware application route for marker semantics. The probe checks a retained pre-erasure database value using the current external ledger, including from a fresh peer without a key. A physical backup restore, production key destruction throughout live caches and backing copies, and generic Q49c predicates, aggregates and sorting remain open. The current key store is process-local. The save timing probe alternated 16-edit blocks of protected SSN replacements and plain date replacements on 128 fresh placements. Each arm had 64 individually acknowledged saves in the packed source. The protected arm used **13 datoms and 357 value bytes** at the median, an extra two datoms and 141 bytes. Fressian grew from 367 to 530 bytes. Both took one durable storage turn.

The 0.18 ms median preparation delta includes crypto and input validation. These short-arm tails are individual maxima. The same gate checked identity-only erasure, preserved bystander bytes, exact resends, a new version, and recovery from a retained source cut with the current ledger in a fresh peer. The C07 marker's tasks, flags, work items and dependencies matched the frozen oracle. Both 513- and 2,000-fact W0 owner retirements matched all assertion identities.
