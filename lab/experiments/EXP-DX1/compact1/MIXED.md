# Corrected writer with readers and a neighboring import

**North star.** P1 pinned reads concurrent with P2 saves, P6 neighbor tails and P8 import progress. [Scope](../../../SCOPE.md) · [Priorities](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

Eight reversed-order windows use the WFIX1 gateway and compact with stored journal rows and checkpointing. Each window begins 64 pinned reader loops on distinct 160-fact subjects and offers 96 live replacements at depth eight. The mixed windows also offer 24 imports of 160 facts through the same database while the live saves run. The corrected importer uses the live gateway's import class and the actual priority admission logic. Both paths use durable receipts and exact original pinned reads. The test reports how many readers and import acknowledgements overlapped the live window, how many offers failed, and the p99 relative to the same path with readers and no import. Short windows, a shared Mac and one-event seed subjects limit the claim.

All **768 live saves and 96 import frames** returned exact receipts. All 64 readers in every window returned at least one exact pinned world during the live window. WFIX1 ran source `0f92704d2` with its live-priority scheduler and ordinary journal. The live readback showed the optional packed-journal and shared-ledger layouts disabled. The 64 readers ran unpaced in the same two-vCPU peer as the writer. Each write p99 is the maximum among 96 offers.

The neighbor import reduced compact live goodput by **24–29%**, and compact write p99 was **2.07× and 1.25×** its reader-only controls. Read p99 was 0.72× and 0.95×. The corrected path's lower mixed write tail coincided with fewer import frames completing inside the live window. The overlap and CPU contention make this a diagnostic on these schedules. The import sender drained all frames after each window and an exact replay advanced neither source position nor native t. [Mac `p2-mixed-b` evidence](SHA256SUMS)

The compact load in Part 1 verified input fact bodies, receipt, contiguous logical positions, final count, index catch-up and a sample of exact current reads. It used a synthetic current snapshot and one native fact envelope per subject. The neighboring-import probe checks the stored value of each imported fact, the original identity and no additional native commit on an exact frame resend. It uses prepared current snapshots. Its sender and readers share one JVM.

The present account loader in HA1 verifies the chained source payload digest, the original normalized receipt, destination rows and the full normalized native feed before advancing the persisted target checkpoint. Activation verifies the sealed source and destination, account, end t and p, sequence, digest and next route generation through a committed source fence and serving-mode target. Its backup and failover tracks separately verify source pins, exact recovery and erasure sequencing. These checks are outside the six-minute load. The neighboring-import probe tests a repeated frame and current values. It leaves historical original-position replay, resume during gateway failure, archive and erasure restoration, verified reverse-index readiness, and source fencing and route publication open.
