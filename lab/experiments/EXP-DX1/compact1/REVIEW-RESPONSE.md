# Response to W2-COMPACTREVIEW

**North star.** P1 exact pins, P2 durable saves, P3 queryable journal and P4 retained-history read cost. [Scope](../../../SCOPE.md) · [Priorities](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

1. **Stored business facts and journal.** Agree with the blocker. Part 1 archived the native 11-datom primitive, which drops ordinary business and journal facts. Part 2 adds actual lean journal rows on the source save, with one row per assertion, retirement and distinct changed child. A separate two-edge index can select W0 worlds at exact cuts. A full business projection, historical generic Datalog / match adapter, existing raw business-row queries and exact cursor translation remain open. The narrow index cannot satisfy those surfaces. [Surface ledger](QUERY-SURFACES.md)
2. **Comparator and attribution.** Agree with the independently reproduced 4.40× and 6.19× measurements and their scope. The older control used root-only changed membership, fewer options and no independent full-feed comparison. Preserve it as a historical narrow-path observation. Isolate physical bytes, journal additions and guard work under an explicitly matched tape, and price the corrected writer separately. The optimized W1/PREP1 control still needs matched full-path producer, native read and response parity before cross-branch promotion.
3. **Replay slope and outlier.** Agree that cold prep and pinned replay scale with history. The checkpoint gives every 64th source event an exact predecessor image, bound to that owner's source, epoch, codec and native transaction. A valid checkpoint caps the replay to 64 events including the carrier. An older pin selects an earlier carrier from its own cut. This design uses bounded predecessor seeks and saves the write for a separate checkpoint directory. Corruption falls back to the verified source events. The original 194 ms read had one event and no per-read stage instrumentation, so it remains an unattributed observation. [Checkpoint design](HISTORY.md)
4. **Erasure.** Agree that rebasing old reads did not satisfy Q49a–b. The revised gate requires an identity-only erase journal, an unchanged first timestamp on repeat, an empty event for a selector that matched nothing, and an opaque envelope reference in every stored copy. A separate durable ledger and a fresh peer check recovery from a retained pre-erasure basis. Production non-exportable keys, physical restore and the full Q49c predicate/aggregate contract need separate evidence. [Erasure design](ERASURE.md)
5. **Activation and seeded roots.** Agree. The original gate evaluated supplied worlds and never discovered their roots. The new reverse probe starts at changed identities and selects placements through the two indexed hops, including ballast and scoped-release cases. A release marker still does not prove authenticated content, changed outputs, withheld/replayed notices or P5 publication.
6. **Large retirement.** Agree. Explicit deltas hit the 512-change request guard. For W0 placements the peer now expands the owner marker into every live assertion ID and the native guard requires the exact predecessor. The gate covers 513 and 2,000 facts. General cross-owner references and cascade rules still need their own scope guard. [Retirement gate](ERASURE.md)
7. **Codebook and migration.** Agree. Bind the dictionary hash to the source so an old assertion cannot decode with shifted columns. An exact portable migration still needs aliases for old receipt/transaction/assertion IDs, an account epoch on cursors and a representation for original multi-owner logical cuts. Q106f requires storage isolation for deep accounts.
8. **Forecast.** Agree with the arithmetic and limits. Treat 730/s and 31/34 ms as the envelope-only priors. The revised test needs stored journal rows, aged subjects, reader and import work and all scheduled offers in the denominator. Peaks and reserves will be reported for each named arm.
9. **Import.** Agree. The six-minute result measures a one-event current snapshot, not historical replay or the production loader. Present-loader staging, validation, resume, visibility and required query materialization need their own checks and costs.
