# What the experiment checks

**North star.** P1/P2/P3 exact reconstructed values, independently checked cut boundaries, durable receipts, and lossless feed. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

| Result or receipt | Content check | Freshness and binding |
| --- | --- | --- |
| Engine attempt and cleanup | Inspect image IDs, local Datomic JAR hashes, process caps, source mounts, mounted file SHA-256 hashes and SQL durability readbacks. Remove containers by their recorded IDs and attempt label. Check that their volumes and the network are gone before releasing the holder's slot. | Fresh attempt name, UUID, exclusive reservation, exact container IDs, source-copy manifest and cleanup record. |
| Native floor sample | Compare requested value multiset, byte count and distinct members to the exact returned datoms. Compare complete acknowledged tuples to the native log by t. The reducer checks dimensions, per-cell counts, t order, and transactor log datom counts. | A fresh native database per attempt. Every timed row names the attempt and source digest. The reducer checks the saved source and slot binding before grouping rows. |
| Compact command receipt | The serialized function checks the existing command key first, then the expected subject and optional account heads. Look up the durable command, account epoch, subject, native t, position, clock and request fingerprint from the acknowledged database. A resend must match the original request. | One new command key per account, assigned only in the native serial turn with that account's successor position. Duplicate and conflict outcomes consume no logical position. The test discards the first grouped result after the real append, compares the resent receipts and native head, and prepares a command from an intentionally older peer value. |
| Layout and import census | Read the exact layout writes back from the native log. Match output adds and retirees to intent. Validate each imported subject body, account ordinal and receipt. Compare each sampled projection to its full fact set. | Fresh scope and expected position ladder. The analysis rejects mixed attempts, verifies actual mount and reservation records, and checks the declared population, progress, index catch-up and WAL boundaries. |
| Temporal and erasure witnesses | Compare current and pinned facts at adjacent microsecond bounds, retired values and clocks, exact resends, an interior group point, independent accounts and one-entry feed pages. Check an erased value at an old cut, its feed and history, surviving other-person data and the absence of the planted plaintext in committed log values. | Every witness uses fresh account fixtures in the owned SQL database. A separate peer process resolves the original receipt and reads the same historical and erased outputs. The test vault demonstrates the marker and key-destruction protocol with a process-local key. |
| W0 domain and TypeScript gateway | Rebuild expected worlds from frozen source facts and their planned account ordinals. Compare each native current and pinned response byte-for-byte to independent O-DOMAIN output, and compare against the frozen answer where native logical coordinates match. The SDK scenario checks grouped receipt identity, interior reads, exact resend, changed-body rejection and feed content. | Verify staged fixture, oracle, release and executed gate bytes, match attempt/source and terminal record counts, bind receipts to their native t and compare recovery from a fresh peer. The reducer retains oracle input and output hashes. |
| Alternating comparisons | Assert offered command IDs and widths, unique receipts, actual native log per physical group, selected exact current and pinned worlds, all-account ordering and scheduled arm order. Price native apply using the emitting writer's native t and datom count. | Fresh, matched 160-fact cohorts on separate databases in the same SQL instance, unique command identities and exposure order, checked before logging arm results. Each writer is identified by a checked, untimed marker and the collector verifies PostgreSQL LSN boundaries, source, slot, attempts and terminal counters. |
| Fleet test command | Report all scheduled offers, in-window goodput, late or missing offers, per-account latency and saturation. Check the full committed receipt against the original command and the final database view. | The launcher checks a clean runtime checkout and generates a fresh attempt and database. The peer checks SQL durability and verifies each loaded account head and committed save. The server operator supplies the pinned distribution and matching transactor classpath. The command has no server execution evidence from this experiment. |
| W0 reverse postings and stored journal census | Compare every emitted posting with the exact native report and compare affected subjects against the frozen oracle. The group watermark uses CAS and accounts for pages with zero mutations. Compare stored journal rows read by native Datalog against the durable log and the original edits and retirements. | Source account identity, new source/index databases, copied oracle bytes, attempt, exact logical positions and native t, slot and SQL durability bind the result. A partial or different attempt fails reduction. |
| Checkpoint and long-history probe | Check checkpoint bytes against the prepared parent and durable report. Check each returned 160-row world against its generated input. Cross-check checkpoint reads against the original chain on both sides of each boundary. Reject a modified digest. | The snapshot binds source identity and exact immutable parent. The four reader processes recover the same fresh attempt, recorded head and native t. The reducer requires every subject, cut and reader terminal record. |

The W2 review's lost replacement response and predecessor-clock findings motivated the order of the claim check and full retirement witnesses. Queue fairness for mixed import, activation and notice traffic belongs to the admission gate after this experiment. Source-level tenant isolation, production key restore and mixed-traffic activation remain separate qualification tasks.

The evidence here supports diagnostic claims and the listed prototype scenarios. The lab acceptance contract, fixture source and their pins are untouched.
