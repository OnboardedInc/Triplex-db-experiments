# Current erasure sequence on Datomic

**North star** P1, P2, P3 and P5. Preserve the shape of assertions, read the erasure sequence independently of the data pin, and fence work that could publish a value taken from an older cut. [Scope](../../../SCOPE.md) · [Targets](../../../TARGETS.md) · [R38](../../../research/R38-erasure-design.md)

The first prototype gates logical visibility and still stores the protected bytes in its lean data and history. It does not erase prior recipient logs, old SQLite files, or filesystem copies of the authority. The released joined and notice paths here are the versions integrated into INT1. The branch-only copy replay in STG1 and settlement and archive paths in ACT1 need the same ticket. General Q49c/Q52 query aggregation, cross-gateway sender recovery, invalidation of existing external deliveries, and restoration of a lost authority need separate gates. The lean native query route already declines engine-side query evaluation.

The guarded-scope and control overhead mode uses identical ordered deep seeds, 500 verified saves per arm, four pinned readers, HTTP body bytes and sampled storage counters. It uses declared protection with zero published erasures and no encryption.

## Native regression

`p2-ledger-24b` verified all twelve baseline routes plus the W0 SSN rule. The original gateway handle, both local replica views, and both journal paths returned the original assertion under the new typed marker. The reopened feed reached the following verified save. The replay importer declined the original field. INT1 Publish left the account at the erase position and refused the old projection. The sender and recipient refused the stale packet, then verified a current benign delivery. The joined marker and chunk header bound sequence zero, and the second attempt lost its commit after an erasure during staging. Restoring the pre-erase backup refused reads while the data was behind the ledger, then returned the original identifier and marker after replay.

`p2-ledger-24a` verified the other eleven routes and exposed the joined fixture's existing refusal to load SSN into its retained inputs. The corrected attempt tests the joined race with a synthetic protected background field. A separate native scope supplies the real erased SSN marker to the W0 policy. The original E-Verify submission is replaced by the erased-SSN task. [Evidence manifest](P2-LEDGER-SHA256SUMS)

## Cost of the guarded read and save

`p2-ledger-overhead-a` compared 15,032 deep facts per scope. Save p50/p99 moved from 10.85/36.58 ms to 32.27/63.18 ms, or 2.97×/1.73×. Pinned read p50/p99 moved from 2.22/8.99 ms to 17.08/47.50 ms, or 7.70×/5.28×, across 8,812 and 3,235 completed reads.

Median save request/response bodies were 7,442/365 B in both arms. The two blocks added 1,069,569 and 1,069,579 B of PostgreSQL KVS values. A direct row request/response was 113/3,654 B in both arms. Median reach response bodies grew from 1,428 B to 39,592 B because protection makes cached closure references ineligible. The comparison prices the current implementation and that cache decision together. A sequence-aware cache needs to bind both inline and reference responses to the same sequence, including retries and reordering. [Evidence manifest](P2-LEDGER-SHA256SUMS)

## Evidence checks

- `erase/apply-native!` compares the committed native erasure record with the exact prepared identity bytes at the transaction it just received. The per-scope external hash prefix binds the ordered command, selectors and original first-erasure instant. A repeat recovers only a matching command and selector list.
- The native regression binds the source file and compiled package digests, gateway image, reservation and a fresh nonce. Its checks read back the held and fresh row, the live and retained replica, the journal, the fresh feed offset, the import frame, the original Publish projection and commit position, the packet and recipient entry, the joined marker and staging attempt, and the restored row. Every observed marker is compared against its original assertion and the published instant. The receiver tests use a seeded packet with exact account, epoch, ordinal and digest. The restore uses the actual pre-erase backup for the same scope and verifies its pre-replay refusal.
- The timing runner verifies seed content, actual write acknowledgements and the pinned reader fingerprints. It records independent wire sizes and SQL byte counters around the arms. The attempt binder is the same as for the gates. Reports describe local observations.
- The acceptance pin manifests contain none of the changed files. No acceptance files changed.
