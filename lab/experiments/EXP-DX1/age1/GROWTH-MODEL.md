# Index growth predictions for one Datomic Pro database

These are pre-run hypotheses for Pro 1.0.7745 and solo K growth on the pooled SCALE1 seed. Sizes count total historical datoms, including retractions. The 0.16B row is an index-size reference for a database with 160M total comparable datoms. The SCALE1 seed's 162.46M business facts also generate journal and storage records. The model switches from bulk to solo K composition around the 430M source estimate. Use the actual settled `db-stats` count to locate the seed. [Seed census](SEED-ADOPTION.md)

Datomic uses immutable shallow segment trees and merges indexed data with current novelty. EAVT and AEVT contain all datoms; in Pro, AVET contains indexed/unique values, and VAET contains schema refs. Application-level ref values in the lean rows are text inside row datoms. The pinned distribution has an index root with a flat directory array and a directory with a flat leaf pointer array. Its directory partition defaults are 2,400 leaves for EAVT, AEVT and VAET (called RAET internally) and 1,000 for AVET. Main and intermediate tiers can each have this three-level shape. A new intermediate tier changes the number of paths a probe may consult. [Datomic index model](https://docs.datomic.com/indexes/index-model.html) · [Background indexing](https://docs.datomic.com/indexes/background-indexing.html)

The second part-one Mac job reported 1,715 index segments for 3,659,560 index datoms at 1,260,314 logical records. At nearby t=61786 the main EAVT had 410 leaves, and the AEVT and AVET main weights corresponded to 454 and 445 leaves at 45,000 weight bytes/leaf. VAET reported one leaf. Full verified backup bytes divided by all visited objects (including log segments) gave about 13 KB/object at both cuts, 21.13 MB / 1,560 and 74.29 MB / 5,719. This average does not separate the root, directory, leaf and log bytes. The table uses estimated serialized directory bytes per leaf pointer (40, 40, 72, 32 respectively). Validate those coefficients by measuring directory objects directly. The model allows 3,000/2,740/2,510/2,600 datoms per leaf and 99% AVET indexing on the seed, 90% after it. It forecasts roughly 180k VAET items from the seed's transaction/claim/schema links and near-zero new VAET items from solo K. The seed's actual compactness and density are the main uncertainties. Each index already has three levels at the observed small cut when it has a populated root. Crossing about 7.2M EAVT, 6.58M AEVT, 2.51M AVET or 6.24M VAET **index occurrences** should first require a second directory at full packing. That expands the root without adding another level. A fourth structural level is not predicted through 8B in the pinned implementation. VAET's sealed-seed population stays below its second-directory threshold. The first intermediate-tier transition already appeared by the small cut for AEVT and AVET with the 32 MiB threshold. Different transactor thresholds and novelty can move that transition. A surveyed root with child roots, or a persistent directory/leaf count or byte total outside ±40% of the forecast at the actual seed and 1B counts, contradicts the model.

| Current person/task read | One scoped AVET identity path and EAVT range per selected entity, plus cache/novelty. At fixed footprint, at most one extra cold directory per tier; number of leaf segments is bounded by rows returned plus adjacent boundaries. | A fixed recent and untouched task each returns the same rows while median AVET/EAVT leaf loads increase by more than two at both doublings. |
| Old pinned read | Resolve position (AVET), find the old EAVT row slice. Old snapshots can walk more segments for edits of the selected entity even when global datoms stay flat. Include recent and quiet owners as controls. |
| Feed page | One AVET range followed by journal EAVT segments for seven transactions. A head request can resolve from recent memory. Old pages may touch more leaves if adjacent logical txs are separated in physical storage. | Leaf reads for fixed seven-entry old pages grow by more than two across matched doublings while page byte counts stay fixed. |
| Save uniqueness and predecessor lookup | Transaction-scoped AVET identity probes and EAVT owner/revision; predecessor row lookup via AVET prefix. Bounded by width, with more directory cache misses possible. | Transactor `tx-with` I/O stats show median AVET/EAVT leaf loads doubling at matched width, pinned per-person edit depth and backlog. |
| Index job | Path choice depends on debt and main/mid populations. A fixed novel batch may merge slices or rewrite a tier. The job's affected segments, bytes and time are not a point-read growth law. | At two doublings, fixed debt and placement produce all-main rewrites with duration and written segments proportional to the entire retained population. |
| Fresh peer's first read | Directory root read volume grows with root boundary array. First read on settled indexes uses the same fixed-width path and loads the few needed segments. Connect can separately replay unindexed tail. | A new peer at zero matched debt reads O(total leaves) from SQL before a one-task read, or first-read leaf loads double with fixed result size. Record connect separately. |
| Backup, full verify and restore | Full copies, hash verification and fresh restore visit all durable segments through the cut. Bytes and duration should be roughly linear at fixed compression, storage bandwidth and index layout. | Native backup verifies comparable bytes/segment at each rung but visited objects or copied bytes stay approximately flat on doubling, or doubled bytes at equal bandwidth require more than 2.5× elapsed repeatedly. |

Collect per-tier root, directory and leaf census in a separate reader after the timed probes. Use peer I/O stats (`dir`, `*-load`, `sql`, cache tiers), transactor I/O stats by transaction t, and index merge/adoption events for the falsifiers. Hold the exact cut, observed data bytes, per-owner history depth, offered save mix and novelty debt in the telemetry. A first peer read tests peer-cache coldness. PostgreSQL and its filesystem can retain data from previous probes.
