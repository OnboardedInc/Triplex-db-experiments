# DX-AGE1 method and boundaries

The tape uses ten deep accounts with 160 current fields per person and four thin accounts with four fields per person. It reserves one person per account idle from the seed, then starts a year later and advances the Mac cohort through two simulated days per round. Million-person seeds cap edit cohorts at 20,000 deep or 5,000 thin people per account and use eight hours per round. The same population, field count and owner order remain fixed across each measured ladder. Tape positions directly determine the identity, record clock, predecessor values and width of each synthetic save. The width cycle approximates the 3,340 / 3,340 / 3,320 W1 mix.

The reference invokes the gateway's storage save entry point with the ordinary claims, current assertions, retirements and complete journal rows. The generator renders the same K storage shape with the shared compact row codec. Each async submission is still a separate native Datomic transaction. It checks the exact requested additions and retractions, prior revision, claim, operation, clock, position and native transaction in the returned datoms. The seed is a common bulk fixture. Its storage density and graph shape differ from the mixed production import.

The fidelity gate reads committed native logs from two new SQL-backed databases. It compares logged attributes, values and assertion/retraction bits, including actual compact journal bytes. It maps storage-local transaction/entity IDs to logical identities and checks native transaction instants for type. Logical record clocks are exact. It checks full live rows against the tape oracle at current and named old cuts and matches feed pages at both bounded and current heads. The page response's availability wall clock is variable.

The native generators use synthetic data and private databases only. They assume an exclusive writer, a fresh matching seed or a verified continuation, an exact prefix and no population changes. A missing or unexpected ACK halts the attempt. Unknown outcomes require exact native readback before choosing a resume position. The benchmark records durability in the SQL store. The save harness invokes the same Clojure gateway path and measures offer-to-ACK with one ordered worker. It leaves HTTP, TypeScript preparation and production burst scheduling outside the measured clock.

The Mac ladder measures backed storage at each settled count. A fresh JVM clears peer process caches. The Linux guest and PostgreSQL caches remain shared and can be warm. Save rates are 3.5 and 50 per second. An explicitly requested job measures request through indexed readback at one cut. A measured overlap requires at least one save interval intersecting the job window. Review the native job log and exact t before comparing tails, especially when index requests are already satisfied. Percentiles are nearest-rank with their sample count. Small single observations expose mechanisms and give weak fits.

Use the lab heavy wrapper with label and measure-holder DX-AGE1 and the engine subcommand age1. The runner takes holder DX-AGE1, run fidelity/scale/successor, and a fresh out name. The scale mode accepts optional saves, deep, thin, low-n and busy-n parameters. It uses local recorded images, fresh managed volumes, the shared slot pool and source hashes. The Mac guards are 5 GiB minimum free host disk, 7 GiB maximum source SQL, and owned temporary copy cleanup. See the server campaign for the hosting assumptions and predeclared numbers.

The successor fixture carries every account at a shared cut and routes logical positions to the original or successor storage. The source product writer is fenced at the serialized native basis. The test checks exact receipt replay, old and new pins, current rows and feed continuation. Its erasure drill records retained copies after native excision and preserves a small in-process marker inventory. Durable publication of an erasure frontier, backup erasure and arbitrary Datomic joins across eras remain open.
