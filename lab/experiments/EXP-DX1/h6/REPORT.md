# DX-H6: W0 movement, publication and reference-order seed

North star: P5 release activation, with P1/P2 latency preserved. **No acceptance is claimed.** This is a source-bound experiment report; complete gate passes do not make the incomplete gates pass. Targets remain unchanged.

## Implementation and exactness

The new `packages/datomic/src/sweepRows.ts` bypasses entity decode/cache/revision/reference repair for full inline sweep pages. It uses bounded whole-page HTTP JSON parsing, **not an incremental JSON tokenizer**. It validates page position/t/reset and root/closure binding once per page, row fixed columns/types/safe position/schema/entity and triple identity/record time/value domain per row, valid-time visibility, and complete visible reference coverage. A fully checked common-layout fast branch avoids dynamic column loops; the original generic validator and legacy decoder remain. Declines fall back to the guarded portable path; VM runs use strict mode so a decline fails visibly. `getReachRowsMany` and H6-authored gateway code are unchanged.

World construction computes each canonical fact key once and sorts those keys. W0 escaping makes the keys ASCII, so JS lexical order matches the old UTF-8 Buffer comparison; canonical world bytes/digests reuse the keys. The worker returns a transferable buffer of outputs/records/world digests rather than worlds. Ready handshakes establish all workers before the activation timer; baseline traffic is established after workers are ready. Fetch/evaluate/publication overlap with at most two waiting results per worker. Publication is invoked in page order, command-ID lookup/dedup and atomic TripleLive preconditions remain, and the resume cursor advances only after ACK. State reads are batched once per page at an explicit head. The final publisher caps two native frames through their ACK; this responds to the eight-worker burst failure, without claiming that a mock test proves live latency.

The 64-subject read page is a real gateway bound: `packages/datomic/gateway/src/triplex/gateway/reach.clj` declines row-page roots above 64 and caps the reached graph at 50,000 entities. H6 keeps that public limit and pipelines ordered page commits rather than changing the gateway. The publisher's64-subject guard aligns with these pages; a separate native frame ceiling was not established, and larger commit coalescing was not qualified.

The independent Python oracle logic and W0 kernel are unchanged. Every subject's oracle reconciliation and published-record comparison run **after the last ACK**, before G1/G2/G5 can say PASS. G1 checks all world digests against fresh preview worlds; G2 checks all output bytes and normalized complete records; G5's expected records are derived from independent oracle outputs. G9 still reads actual stored publication journals. The old cache-count wrapper is removed: normal clients use package byte budgets (128 MiB entity/32 MiB rows), raw sweep clients use the supported 1-byte minima without cache insertion. No memory claim depends on that old wrapper.
