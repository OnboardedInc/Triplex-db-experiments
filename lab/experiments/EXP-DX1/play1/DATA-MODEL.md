# Playground data model

**North star** P1/P4 temporal reads over a representative graph, P2 field-level saves, P3 per-save feed and P5 release answers. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md).

Structural sources are the Onboarded Prisma schema and the Task, Placement, SubtaskSubmission and CustomAttributes domain models. Triplex's W0 schema supplies the placement-owned answer/document pattern and identifies SSN as protected. All values and IDs are generated independently. [W0 schema](../../../../packages/w0/src/schema.ts)

| Playground subject         | Source structure and fields                                                                                                                | Fact representation                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account                    | Account.uid, Account.isTest                                                                                                                | Opaque account ID and synthetic display name. All accounts share one Datomic scope.                                                                                                                       |
| Employer, client, job type | Employer, Client and JobType each have required uid, name and accountId                                                                    | Account-owned named subjects. Placements hold typed references to them.                                                                                                                                   |
| Employee                   | Employee.uid, accountId, firstName, lastName, middleName, metadata                                                                         | Stable person subject, account ref and generated display name. The small status, role and note projection is editable. Deep people include individual name facts and synthetic protected identifier text. |
| Placement                  | Placement.employeeId, employerId, clientId, jobTypeId, starts/ends via placement facts                                                     | Employee-owned subject with typed reference facts and synthetic start date.                                                                                                                               |
| Task                       | Task.employeeId, Task.taskTemplateId, Task.status, startedAt, progressNumerator and progressDenominator                                    | Task subject under a placement or employee, with explicit status, form-version reference, start date and progress.                                                                                        |
| Subtask and field value    | Subtask.taskId, Subtask.subtaskTemplateId, SubtaskSubmission.subtaskId, FieldSubmission.fieldTemplateId and JSON data                      | Status on a task-owned subtask. Each value has its own subtask-owned subject and field key, keeping field edits independently versionable.                                                                |
| Custom value               | CustomValue.entityType, entityId, value, customPropertyId and accountId. CustomProperty.scalarType and isSensitiveInfo describe the value. | Employee- or placement-owned subject and a generated value. The property key is in its subject path.                                                                                                      |
| File                       | TaskFile.taskId, name, mimeType, size, checksum                                                                                            | Task-owned subject with synthetic file metadata. The compact representation has no binary attachment body.                                                                                                |
| Form and verification step | TaskLineage, TaskVersion, TaskTemplate, FieldTemplate.path/type/required and SubtaskTemplate describe the form.                            | Account-owned form versions and step/field subjects, referenced by task. Task-owned verification results carry status. Release policies are content-addressed configuration.                              |

Account-qualified IDs and child paths encode ownership. Parent-child walks can use the generated roster and exact native rows. Shared references are explicit. The thin profile deliberately projects four facts per employee; the same catalogs and identity grammar apply. The fixture deliberately omits provider records, authentication, integration credentials, network identifiers, raw attachments and jurisdiction policy decisions. The playground never generates a plausible SSN or a routable address.
