# DX-RD1 part 2
The slow server blocks completed about 224 gateway fallbacks per second and only 4,114 reads per second overall.
The read workers also sometimes took a long time to handle replies that had already left the gateway.
Recent receipt reads and long-held snapshots need older versions. A past valid time can still use the latest receipt.
The new fallback worker handles gateway calls and decoding while the other workers keep serving local reads.
It can combine calls for the same cut and reuse complete answers for cuts the source has already closed.
The writer probe now records pauses from the write gateway's own log in each of its four blocks.
The server runs will determine whether these changes reach the four performance bars.

North star P1, P4 and P7. Exact concurrent reads, weighted pulls and memory per touched subject. Part 1 evidence is at `89cf9d4d2`. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

1. Mechanism. `miss-probe.ts OUTPUT SLOT SECONDS SEATS mechanism` runs 0, 0.5, 1, 2 and 5% in both directions on the same native roots and two real older cuts. Each read is checked at its requested cut. It records open fallback seats, local completions during waits, native admission and work spans, and time outside the gateway. The fixtures take their old cuts before the local copy starts.
2. Law. `X ≤ min(Xlocal, C/(f × S))` with `C` admitted gateway slots, `f` the observed fallback share and `S` the sum of admitted service for one miss including repairs. `X = N / E[cycle]` also charges admission, callback, local scheduling and split waits to the closed population. The archived cohorts were 72,927/s at 0.0116% versus 4,114/s at 5.44%. At two permits the slow rate implies 8.93 ms admitted work per miss if the gateway alone saturates. Holding the fast local cycle fixed would require about 4.33 s of fallback residence to get the observed slow rate. Use the independently bound trace sample in `archived-fallback.ts` to test both approximations.
3. Age and budget. The frozen draw is 80% latest receipt, 15% among the latest 2,000 receipts within an hour, and 5% latest receipt with past valid time. The sampled archived P4 misses had been applied 472–493 s earlier. In practice a filter with past valid time can be recent in record time. A split read, a release with a pinned cut, or a client across a stall can hold the same record cut much longer. `history-budget.ts` replays frozen offer times and subjects using real packed replacement bytes and reports closure misses by age at 64, 192 and 512 MiB. It uses a synthetic per-update width and one entity per root. It measures history cost separately from eager current copies and does not establish the per-untouched-subject RSS bar.
4. Cheap fallback. `--replica-historical-fallback lane|batch|revision|install` enables cumulative treatments, with `off` as control. The bounded worker handles native calls, decoding and observation. `batch` combines up to 16 already queued requests for exactly the same record and valid cut. `revision` uses up to eight cut-scoped gateway sessions and multi-version decoded keys to avoid repair and duplicate decode. `install` stores demanded exact rows in a 32 MiB aggregate replica cache. Item 3 uses alternating arms at 5% old cuts in `miss-probe.ts … treatments`.
5. Recovery. `miss-probe.ts … recovery` drops the active seats to one quarter while preserving in-flight reads and the basis mix. The combined arm keeps the middle cut with 192 MiB closure retention and installs the older cut on demand. It counts fully contained reads per second, reports the ratio to the native low-fallback arm and makes no 41,392/s server claim from the Mac.
6. Writer attribution. The archived read peer served 776,520 reach and 712,978 reach-many exchanges. Neither was on the write peer's route map. The separate writer JVM gives no direct allocation path from local reader work or ordinary fallback decode. Indirect effects on shared scheduling, storage or the `/begin` path remain possible. DEEPTAIL bound 42 direct pauses and eight predecessor waits in a different deep run. The updated OFF–ON–ON–OFF probe seals write-gateway JFR pauses against the fresh run, slot, source and boot. A pause log cannot measure allocation volume by itself.
7. Physical handoff. The forecasts were committed at `3125ea58b` before execution. If the driver exceeds 0.70 in the required windows, keep the arm unjudged and isolate the saturated role before repeating unchanged offers. [Commands for server 1](SERVER1.md) · [Pre-run forecasts](PREDICTIONS-P2.md)
8. Audit. Probe counts compare full-row digests, stamps and cardinalities to the receipt model before counting. Sums reconcile issued, completed and drained calls. Native timing binds both HTTP parent IDs and returned gateway IDs to fresh requests, the native source build and the owned slot. History sweeps compare full packed value and version to the offer-position ledger. Worker batches match the exact scope, root and both clocks. Installed entries require an applied source position or sealed record time, complete closure and a half-open valid interval, and clear on replica rebuild. Terminal worker counters must reconcile and the 0.70 check includes the new worker. Pause summaries verify the raw JFR digest, event count, run, slot, source and boot. Mac diagnostics stay diagnostic.
