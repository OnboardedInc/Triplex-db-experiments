# DX-RD1 Datomic readers
The driver checks each read against the expected answer before discarding the raw result from long, fixed windows.
It keeps the counts and latency distributions used by the verdict, even when a write receipt arrives late.
The sender now scans less data, and maintenance waits until ten milliseconds inside each measurement window.
On the Mac, the old cut returned the same stored answer whether it came from the replica or Datomic.
The new option lets older reads stay local when all the records they need are still present.
The four-block Mac run kept the same writer commands and gateway reads. Only the two middle blocks ran local readers.
The 70% driver limit, writer isolation and stress goodput still need the physical server measurements.
**North star.** P1 exact concurrent reads and writer isolation, P4 weighted pulls. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

1. Fixed v3 and ordinary deep windows use bounded rolling verification in replica/worker-journal mode. Split steps fold against ordered copy applications. Receipt, sweep and post-prefix records retain the exact original spill path. `--read-retention raw` is the collection control.

Server driver check `DX_BARE_METAL=1 DX_NS_PROFILE=v3 DX_STUDY_LEVEL=summary DX_CPUS_GW_READ=4,8 DX_CPUS_DRIVER=3,5,6,7,9,10,11 DX_MAIN_CPU=3 DX_WORKER_CPUS=5,6,7,9,10,11 DX_DRIVER_MEMORY=48g bash lab/experiments/EXP-DX1/t1/study.sh tx2-dxt1-rd1 --reader-threads 6 --reader-trace-every 64 --receipt-capture replica-worker --expected-state-retention worker-journal`. Forecast 0.60–0.90 maximum stress-window reader mean. Read `client.stressHeadroom` for the 0.70 test.
3. Same-site remote-six then remote-twelve would distinguish placement from capacity. Relay one ordered replica feed and receipt/basis control stream, keep the writer and its publication clock together, and spill remote. Forecast at twelve on a second machine 68k/s at 256 and 33k/s at 1,024 before product repairs. The local thread-count flag leaves readers on the same host.
4. Mac `reader-cost.ts` used four matched 65,536-read runs on an immutable fixture. Issue plus observe was 1.10–1.32 µs/read. Sender recording fell from 0.63–0.65 to 0.32–0.35 µs/read. Collector unpack plus comparison rose from 0.13–0.14 to 0.34–0.37 µs/read. The historical physical comparison cost 2.35 µs/read and the whole final analysis 7.37 µs/read. The fixture omits gateway delays and disk timing.
5. Audit. Rolling comparisons bind each record clock to its requested receipt position, check all model fields used by the existing comparator, and reject a late model frame inside a closed cut. Transport checks batch sequence and terminal counts. The journal read-back binds run, source, slot and frame content before the existing independent replay and eligibility checks. No acceptance pin changed.
6. Weighted misses. The aged server sent 3.737% to the gateway with only two waits for a newer position. Four directly sampled misses were already applied 472–493 s earlier. Local service means were 47 µs server and 46 µs Mac. The archived worker-level floor is unknown. New witnesses distinguish evicted clocks, open clocks, missing entities and incomplete row metadata.
7. Mac Datomic reproduced the time-only fall-through with a fresh strict scope. The zero-history copy advanced to position 2 and sent the old cut to Datomic. The 616-byte copy still served it locally. `node --import tsx lab/experiments/EXP-DX1/rd1/history-probe.ts prepared` predicts three total diagnostic exchanges across the control and closure probes. On the paired server workload predict 0–0.3% weighted fallback at the young head and 3–5% when aged with the global policy.
8. Maintenance and sender. The monotonic retry starts 10 ms into each planned bin and retains the original completion check. Five local tests include simulated 1.8 ms early wakes and ordered equivalence over 47,000 ACKs with idle ticks and expiry. The ring holds 2,000 ACK objects and sends only new entries in delta mode. The 277 ms GC remains a historical observation. On the v3 command above predict 44/44 maintenance bins and a steady queue peak of 1–2. V8 pauses still need measurement.
9. Recovery. `node lab/experiments/EXP-DX1/rd1/recovery-routes.ts REPORT_JSON` reproduced 67,617/s after the four stress cycles below 1% fallback and 4,836/s after the other fourteen. Their recovery fallback rates were 0.0028% and 5.05%. Returning to 256 does not restore local-cut coverage or remove gateway repair and decode. The official pooled 30 s offsets were about 18.7k/s against 41.4k/s. Forecast zero qualifying offsets with driver changes alone.
10. Writer isolation probe. On the prepared Linux stack run `node --import tsx lab/experiments/EXP-DX1/rd1/writer-probe.ts OUTPUT` with the existing write/read endpoint and trace identity, `TRIPLEX_NODE_MAIN_CPUS=3`, `TRIPLEX_NODE_WORKER_CPUS=5,6,7,9,10,11`, `DX_RD1_WRITE_TRACE`, `DX_RD1_TX_PID`, `DX_RD1_WRITE_PEER_PID` and `PGSERVICE` set. Enable native I/O stats, scheduler stats, WAL timing and perf for the existing role masks before running. Four 90 s blocks replay the same frozen clip, one exact gateway pull per second, and a matched index request. Predict ON native p90 at 1.15–1.25× OFF and about 89k/s local replay with 15 MB/s numeric spill. Under 1.05× in both ON blocks weakens the host-only explanation.
11. Mac Datomic used six-second blocks and two parked/replaying workers. Each arm had nine matched primaries and six exact gateway requests. Recorded replay was 0 / 48,128 / 48,128 / 0, with two 8.26 MB numeric spills and both scratch volumes released. This native Mac run took 35.2 s and did not measure Linux perf or PostgreSQL WAL.
12. Probe audit. Fresh named scopes bind the frozen tape to assertions and receipts. Each gateway result matches the seed model at its exact named cut and makes one request. Native joins require the recorded source and slot, this attempt’s trace ID and the receipt’s Datomic t. Runnable and WAL readings bind the same Linux boot and PostgreSQL statistics epoch at both boundaries. The Mac run checked the matched workload and the switch.
13. Product limit. Four low-fallback stress blocks averaged 72.9k/s. Fourteen averaged 4.1k/s as old-cut reads competed for gateway admission, revision repair and row decode. Twelve remote workers alone were forecast at 0.48 of the 256-reader rate. The largest product opportunity is avoiding those requests. Append `--replica-history-coverage closure` to the same server command with a fresh tag and the same 192 MiB budget. Forecast weighted 4.5–6.5k/s if fallback halves, and a stress ratio of 0.55–0.75 if most misses come from the global floor. The 0.90 bar stays open.
14. Closure audit. The option keeps proven clocks within the position window. It answers from exact versions for every reachable entity, including valid-time filtering. Any evicted dependency falls through at the unchanged cut. A Mac Datomic update showed the unaffected root stayed local and the changed root fell through with zero retained history bytes. Tests cover held group clocks, an expired link, a copied image and an exact wide integer. No contract pins changed.
