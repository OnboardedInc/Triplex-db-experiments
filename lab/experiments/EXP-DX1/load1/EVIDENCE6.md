## Acceptance and receipt audit

- `overnight.ts` checks the archive bytes, records, frame position, input size, attempt identity, slot, source and clock bridge before summing adjacent intervals. The mean is from a frame-for-frame partition. Durations that cross boundaries remain residuals.
- `storage.clj` derives the predecessor from a single canonical stream claim. `commit.clj` checks the prior durable claim on the native transaction basis; an absent claim aborts the suffix. The existing receipt path still depends on the committed position and command. The optional field is used only with the explicit experiment option.
- `Snapshot.open/write/verify` checks the destination manifest against the source/width/scope binding. Every entry reconciles its operation contents and original identity with the claim and committed feed. The independent pinned sweep compares every typed imported row at the cut. An ambiguous response must recover the original claim. Ordered commands add the stream seal and fixed ordinal to the existing fact digest. SQLite advances only across contiguous complete frames.
- `live.ts` checks position and typed read payload for each live offer, then matches each commit to its original native response and the fresh feed in the same scope. The window marker reads the exact pinned rows and IDs of a contiguous checkpoint. The lost-reply fixture uses normal transport and claim lookup, with a separate duplicate, backdate and retirement exercise. Local reopening checks saved receipts against the live destination, then sends on a new transport sequence. The rejected gap must return the typed native reason and leave the claim absent.
- `live-evidence.ts` reopens the fresh input tape and checks nonce, Git revision, slot, scope and scheduled offer for every row. It independently reconstructs the outstanding counts and live pressure from intervals, checks native order, bulk hold overlap, ready-live grant metadata, measured frame size and the window marker’s bound receipt. The runner records hashes of the tested source and built code. The controller preserves all offer misses and binds transferred bytes to the assigned machine and attempt.
- The comparison emits counts and ratios against each control. After transfer the controller recomputes both comparison files from the validated completed arm set and ensures the original arm order. No Mac timing becomes a verdict. The accepted P8 row additionally needs the frozen scorecard workload and both population sizes.
