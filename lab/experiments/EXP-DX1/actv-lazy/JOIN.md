# Publish, changed outputs and recorded notices

North star P5 with P1/P2 live traffic. Measure from receipt of a previously unseen W0 document to the first exact read, concrete changes durable and notice debt durable. Sending has a separate clock. [Scope](../../../SCOPE.md) · [North star](../../../NORTH-STAR.md) · [Targets](../../../TARGETS.md)

1. Use the account’s native Datomic serial predecessor. Bind its source identity, enrolled census, business instant, prior release, notice tail and interpreter. Compile and hash the offered document after the offer. An admission race retries from the new cut. Reusing a command ID recovers the original receipt only for the original request.
2. Start with a verified source census and a fresh recipient epoch. Existing item sequences, pending work and inboxes need an explicit migration. Baseline enrolment can visit every person and is charged separately. It sees no proposed release.
3. An immediate release appends one LAZY activation marker and the NOTIFY1 notice event and tail together. The event binds the rule bytes, source cut, old release, census, previous event and version of the selector. At restart these durable bytes determine every owed creation, changed payload, reappearance and retirement at the original cut. A receiver can remain offline.
4. Use DELTA’s rule declarations and ordered ranges for MINWAGE, EVSTAT and PAYCHG. Index pay, floors, the two location links, pending TNC dates and approval-sensitive pay differences. Keep weekly minutes, answer text, task deadlines and protected identity values outside the notice index. An overtime-only edit owes zero notices. Changing only an existing document lead time also preserves its expiry notice. Changing covered document types requires the full notice census.
5. Enrolment stores authenticated index pages. A normal direct save updates source and its clock. A reader-only edit writes zero index or notice facts. A notice-relevant save also records an ordered NOTIFY1 event. A changed posting adds one bounded leaf revision in the same transaction. Unchanged posting bytes need no revision. Shared edges, validity changes or an incomplete index fall back to exact source coverage. The dispatcher can rebuild a selection at the event’s immutable cut.
6. Use the actual NOTIFY1 dispatcher and transactional receiver. Derive a deterministic candidate page from the source recipe. Commit the item ledger, pending packet and cursor together. A lost receiver ACK replays the original packet. A second release or save cannot cancel earlier debt. Account scope and epoch bind every operation.
7. A connected LAZY reader obtains its authoritative position at request start, selects the winning assertion at its business time and rechecks erasure before returning. Its cache is populated on demand. A delayed live calculation cannot be published at another cut.
8. The owner’s stored-output mode writes actual changed task, flag, obligation and work-item values and deletions in bounded chunks in the same native Publish transaction. Domain changes follow DELTA’s projection definition. For a literal full-envelope contract the envelopes option physically stores every returned W0 byte, including release, basis and trace. A recoverable recipe alone is reported separately from concrete stored values.
9. A fixed-cut edit fully covered by output ranges can read their candidates. A display-only change without an index requires a source census to materialize its changes. First publication establishes the full baseline. An oversized or invalid transaction leaves the earlier release visible. No background worker can finish an incomplete release and claim its original ACK met the bar.
10. With 100,000 or 1,000,000 members, receipt-only Publish has one native commit and four account-level fact changes, independent of recipients. The stored-output mode adds chunks proportional to changed bytes and computation proportional to candidate or census size. With 64-member pages a full path covers 1,563 or 15,625 pages. Give measured byte and time projections with the local fixture density and distinguish them from a scale verdict.
11. A source save at a later business instant cannot discard an intervening expiry. Record unpaid boundaries before the later event or refuse the transition before it changes authoritative state. Dated corrections retain the preceding valid interval and check the original native feed for intersecting versions. Protected E-Verify is excluded pending an owner ruling. Explicit refusal leaves the original debt and clock inspectable.
12. Prove visible reads, physical stored values and owed effects independently. Stop the writer after commit and before reply, reopen without its caches, change a two-hop dependency, cross an equality boundary, roll back while the recipient is offline, and lose an ACK. Compare the three histories with Python W0, including an unseen document and subjects with no facts.
