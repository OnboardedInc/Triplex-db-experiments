# After the receipt

Publish still commits the release, its source cut and the notice recipe together. A settlement worker reopens that receipt. It writes one bounded page and the matching restart cursor in the same transaction. The value and notice archives use separate native scopes on the same writer. That keeps settlement traffic out of the source feed that ordinary saves have to inspect.

Values are scoped to one immutable receipt. A newer release effective at the same or an earlier business time can stop the unfinished value copy. Any completed old pages remain usable at their original cut. The notice worker finishes every event in order, including one whose value copy became obsolete. It commits addressed notice bytes with its item state and cursor while the recipient is offline. Delivery later uses the same ordered receiver and original replay identities.

On startup and on a local Publish or receipt retry, the worker opens the durable tail. An active scan checks for debt appended by another publisher before going idle. A separate publisher needs an explicit call to wake the owning worker after a Commit, or to route receipt replay to it. Fleet-wide durable wake routing and admission remain open integration work.

The archive reader uses a stored response only at the receipt's exact record and valid-time cut, with the same release, epoch and erasure frontier. It derives from the receipt's pinned source when a page is missing. A subsequent live save takes the ordinary current-read path. Protected inputs need a retention decision before this archive can record them.

Bulk frames carry W1's `activation` or `notice` class on the native claim. The producer uses round-robin turns across ready accounts, live preference, a bounded bulk turn after eight completed live saves, and a duty cycle. Each frame is constrained by an 8 ms W1 estimate and the native row and byte limits. The estimate cannot preempt a submitted database commit. P6 needs observed live and neighbour p99 ratios, including stalls and backlog.

W1 implements its native queue per Datomic connection. The application queue shares admission across the source, archives and neighbour in these trials. A production installation needs the same admission ownership across hosts to preserve the one-in-flight bulk bound.

The six component windows keep the receiver offline and leave the individual notice clock empty. The optional settlement windows price both durable endpoints and report ordinary save and read ratios at 3.5 and 23.5 saves per second. They use a separate account with matched address and stamp saves for the loaded and control windows. The retained W0 source witnesses are unaffected by these two edits. Each terminal clock identifies its own archive cursor. The paired metrics include the exact interval with unfinished settlement and its sample counts. This diagnostic does not replace the frozen interference trace.

The first Mac pricing attempt stopped before either window. It was waiting for a timing lock whose owner was waiting for its heavy token. The owned volume and reservation were released. A subsequent acquisition exits promptly in that situation, and a scratch-lock regression verified refusal without entering the foreign timing window and correct release of a free lock.

Receipt-only Publish reads the epoch, policy history, notice tail and closed source prefix. It adds four fact changes and carries the roster hash. The roster size changes neither the number of writes nor the need to look up a person. Keeping settlement state in the side scopes also keeps the source prefix from growing with every archived page. Enrolment and later settlement still scale with the population.

At the observed encoding density, one million deep people would use about 48 MB of notice leaf values and about 103 MB of durable address bytes. At 4.5 million thin people those figures are about 47 MB and 468 MB. These count encoded values and keys without native metadata. P7 charges memory outside Postgres, including gateway and transactor residents. A cache-free reader opens without allocating memo entries for the roster. The full process accounting needs a native size comparison.
