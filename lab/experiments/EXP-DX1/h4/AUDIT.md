# DX-H4 observation-to-verdict audit

North star: make P1–P4 diagnostic verdicts match `lab/TARGETS.md` without changing bars.

- `lib/maintenance.ts`: completed job content checks include database, UUID job, requested transaction, gateway timestamp shape/order and completed flag. Fresh request/response timestamps use the driver's own monotonic epoch and enclose the gateway execution. The per-window predicate requires matching phase and both bounds strictly within the current window. A failed or timed-out request never counts. Raw gateway wall timestamps remain in the event. The recorded OM2 regression reproduces the old `[1,0,0,0,0,0]`; simulated driver bounds exercise the new measurement without inventing historical bounds.
- `driver.ts` history: growth still requires depths 3/10 across the entire matched sample. Each Datomic depth additionally requires its own completed request-index within a 60-second request/response budget before measurement, and at least 10,000 correct measured pulls per depth. Missing prerequisites make the comparison ineligible; the p99 bar remains 1.1. Mean and p50 ratios are diagnostic. A zero-reader baseline has no history read comparison and is explicitly unjudged.
- Baseline loader: requires zero-reader mode, exact generated trace digest, seed, subjects, composition, lane, identical harness sources, completed finalization, zero pending commands, successful original background commands and no observed incorrect reads/errors. The raw writes SHA256 binds the supplied file. Every denominator window must be covered by the baseline's actual offer horizon. Both arms extend to the same predeclared trace duration. The pair wrapper uses distinct fresh stack prefixes and copies raw baseline writes and report without rewriting either.
- Publication: the existing observer validates submitted/final position arithmetic, tagged integer bytes and operation identity before writing the durable source publication record. The new instrumentation records actual before/after witness times and copies optional response diagnostics; it does not replace publication with ACK. Source witnesses stay on the committing thread. No latency is subtracted from any bar.
- Side worker: the unchanged FeedConsumer algorithms still check transaction order/digests, affected subjects, correction ranges, durable effects/checkpoints, publication clock/key/digest, crash recovery and replay. ACK races now defer intent validation instead of skipping it. Outstanding intent checks invalidate finalization. The side worker is explicitly pinned to the original main-thread write-peer URL; regular reader workers keep the read peer. A final structured snapshot returns actual counters, first deliveries, lag samples, crashes and duplicate-effect count; worker failure rejects completion. Read-your-own-write observations keep their ACK basis and go through the same final expected-world checker; unresolved pulls invalidate finalization.
- Commit breakdown: actual monotonic timestamps form segments; only finite nonnegative observations enter histograms. Missing observations remain absent, never zero-filled. `driverOwn` includes per-command offer queueing, all work after transact returns (including after ACK), plus publication fsync inside transact. This is apparatus attribution, not store CPU attribution; quantiles are computed over per-command sums.
- Existing verdicts: correctness-qualified goodput, all writer/read latency thresholds, duplicates/lost-ACK resolution, feed replay, history growth and P5 seams remain. No acceptance contract, pinned verdict or scorecard is changed. Smoke reports and local numeric predicates remain diagnostic until independent review.
- Stack: the wrappers bind exact created container IDs/configuration/source/build hashes, expose no gateway ports, and retain source logs and raw output on failure. All kinds acquire the shared measurement lock before creating containers. Cleanup checks owned container/network/volume inventories before releasing that lock.

The run report will distinguish implementation, focused verification, actual measured results and outstanding limitations. This audit describes the code predicates; it does not certify that an unexecuted run passes them.
