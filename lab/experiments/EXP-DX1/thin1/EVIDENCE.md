# DX-THIN1 evidence

Paths below are relative to the durable `evidence/DX-THIN1` directory. From that directory, run `shasum -a 256 -c` with the absolute path of this experiment's [SHA256SUMS](SHA256SUMS). The manifest seals each database. All remaining WALs were empty. The sidecar receipt records their mutable SQLite reader lock files separately. Use immutable, read-only SQLite access for inspection.

The controlled native comparison seeds eight facts per person in 32-person transactions. Every fiftieth person receives one later write. Seed wall time includes receipt logging and journal checks. Activation includes evaluation and durable publication. Durable readback and both offline oracles run after the activation clock stops. Long stages can include a shared measurement-lease handoff. The native driver and reader run in separate OS processes. Before design, the per-component census used shorter synthetic row IDs and the existing compact driver model in its own process. Native SQL role measurements followed when the holder-managed SQL stack was ready. PostgreSQL sizes include the table, TOAST and indexes. RSS sums for PostgreSQL can count shared pages in several processes.

The first pinned read selects a cut before admission. The 100k current-read group includes reads that follow a write acknowledgement, when admission may already have occurred. The 29-sample diagnostic reads previously untouched people in an open reader. A separate first call includes opening the composition. Each comparison arm starts fresh gateway processes and creates its reader after seed. The slot manager's readiness probe checks a separate health database. Application scopes receive only the requested workload.

For a fresh Mac arm, run `managed.ts --build CONFIG` then `managed.ts --arm CONFIG all|touched SIZE NEW_EVIDENCE_DIR GUEST_NODE` through the lab heavy runner using Node's TypeScript transform. CONFIG is a fresh directory beneath the worktree's ignored runs directory. The optional `DX_THIN_DIAGNOSTIC_JDK` selects the verified profiling image and four cost-only phase samples. It is unnecessary for the normal comparison.

On the prepared physical server, `node --experimental-transform-types lab/experiments/EXP-DX1/thin1/queue-bench.ts --launch BATCH UTC_CUTOFF PREPARED_DIRECTORY` takes the BM1 day lock, records physical CPU placement, runs two fresh SQL stacks sequentially and releases their resources. Use `--plan` to inspect both rungs. At 1M and 4M the active sets are 20k and 80k. I expect roughly four times the import storage and active replica payload on the larger rung. First-read tails, shared cache behavior and full outbox publication time require measurement. The Mac comparison exercised a pinned sweep after the live writes. Concurrent activation under the frozen trace remains a separate gate.

The prepared directory supplies a clean `repository` with the pinned O-REPLAY commit, `tools/bin` with Node 22 and pnpm 10.11.0, the offline `pnpm-store` and `docker-config`. The physical daemon must already contain the images used by the existing DX1 stack runner. Batch status, topology, cgroup cleanup, phase measurements, raw per-person publication and hashes live under the directory's `state/evidence/DX-THIN1` tree.

The 100k comparison binds both arms to `65a1bafa`. The final native smoke binds to `482e96b10` and checks 100 domain and outbox records, split reads and 29 first current reads. Between these revisions the shortcut was fixed to the three exact release hashes and additional public-entry checks and measurement diagnostics were added. Use `--composition reach-touched --read-path gateway` for demand admission and `--composition reach --read-path replica` for the eager control. Apply scope feed entries to `ThinRoster.apply`, then call `activate` with a captured basis, the independent roster digest and `mode` set to `dependencies` or `full`. The native adapter in [trial-store.ts](trial-store.ts) supplies pinned full worlds and the guarded outbox publisher.
