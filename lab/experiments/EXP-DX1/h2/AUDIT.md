Limits: the existing G4 is PARTIAL (no live abrupt-stop cycles), G6 NOT-RUN, G8 missing. G5 checks the existing ACK/returned-delivery path; it does not add a new independent readback of every committed outbox row. The latency pair is diagnostic: evolving store, no clone/A-A calibration, current-position uniform readers rather than the complete TARGETS read mix. This is never converted into a P5 acceptance PASS.

`w0-journal.ts` additionally enumerates identities from ACKs in this private fresh scope, requires dense observed positions 1..source head (otherwise refuses), and point-reads every requested stored public `Triples.transaction` record. Each record must match its recorded transaction ID and position and carry changes. No count is folded from ACK payloads. The engine test compares every returned journal page byte-for-byte with the old public `transactions` route on a 50-subject seed that fits its cap; the 200-subject failure of the old route is retained separately.

`w0-claims.ts` uses the exported `DatomicClient.claim(db, commandId, position)` to read the real stored command claim at a captured source head, then public `Triples.transaction` to verify the stored transaction ID, command ID and eligible position. No ACK cache resolves lost ACKs. The small-store engine gate compares present and absent command lookups byte-for-byte with public `transactionByCommand` before the larger activation. This W0-only workaround avoids that method's whole-fact scan without changing packages.

`rootAttributeRows` (in `w0-public.ts`) selects precisely the root scalar rows the old full reach read filtered for retirement. It rejects malformed/future source heads and rows outside entity, attribute, recorded-position or valid-time bounds. The engine gate compares all returned row bytes with the portable graph reader on ten subjects at both sides of a real scalar retirement. The frozen commands, retirement preconditions and oracle checks are unchanged. Agent events without scalar replacements skip an unused read.

`matchW0Live` uses raw `write.scheduled` through `write.ack` for the primary commit clock, including late ACKs after the window. Transact service duration remains a separate `commitService` diagnostic. A regression test distinguishes 200/400 ms offer-to-ACK from 10/20 ms service, so resetting the primary clock at service start fails. `normalize.mjs` never overwrites original receipts; it binds receipt/raw/matcher hashes and emits a new diagnostic derivation without adopting a semantic PASS.

`activation-pages.ndjson` persists completed page metrics with attempt/scope/basis after verified ACK publication, so a later failure retains completed-page observations. `exit.json` records the real child exit code/signal; it never grants semantic acceptance.

`TERMINAL.json` for the failed final run is a diagnostic derivation only: it hashes the original FAIL receipt, actual exit, command, cursor, completed metrics and evaluation bytes; reports only ACKed pages; independently compares captured source hashes before subsequent edits; explicitly leaves full wall/rate/ratios null. It does not promote prefix observations into global gate PASS. `cleanup/cleanup.json` records actual Docker removal results and fresh empty owned-prefix inventories; no semantic acceptance is inferred. The final source edit retains nested reader failure causes and raw failure events; it changes no check or verdict.
