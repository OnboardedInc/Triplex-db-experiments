## Change

`QleverConnectionMode` accepts `keep-alive` and `per-request`. `makeQleverClient` and `makeQleverRuntime` accept `connectionMode`; `TRIPLEX_QLEVER_CONNECTION_MODE` selects it for existing harnesses and worker processes. Explicit options take precedence. Unknown modes throw. The absent-selection default remains **keep-alive**.

Keep-alive retains fetch unchanged. Per-request uses Node HTTP/HTTPS with `agent: false` and `Connection: close`, avoiding pooled sockets even when another client already has an idle connection for the same origin. A header alone on fetch was rejected because that request can borrow an existing socket. Query, update and command share this transport; authentication, request IDs, signals, timeout and byte budget still pass through the same request handling. Native cancellation still uses its separate WebSocket. The direct endpoint is required: fresh transport returns redirects as HTTP errors rather than following them. No dependency, server or container lifecycle changes.

New QLever receipts include mode in the gate envelope, NS, P5 screening, GS, C8 round timing, J01 receipts, QG1 P4 samples and package experiment reports. The QG1 direct-fetch diagnostic records its actual fixed `keep-alive` mode rather than claiming it uses the client option. Historical receipts were not rewritten. Package README documents the API and transport boundary.
