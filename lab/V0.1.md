give it more budget, but lets work towards a v0.1 of this project and keep our budget for now".

## What version 0.1 is

One branch, one database, one scorecard, one playground.

1. **One branch.** Everything the product needs is merged on one branch (`exp/DX-INT1` today), builds from a clean
   clone with one command, and passes its correctness gates. Work that is not merged there is not in version 0.1.
2. **One database.** Every account lives in one Datomic database on Postgres storage: ten deep accounts of 100,000
   people, wide thin accounts, and small accounts.
3. **One scorecard.** One command runs the fixed workload on a bare-metal server and prints, for each of the nine
   priorities, the bar, the measured number and pass or fail. It runs twice: on the fresh database, and on the same
   database aged to 1 billion records.

4. **One playground** (Sam, 2026-11-20, second message below). One command starts the product on a laptop, loads a
   synthetic test data set that is stored in the GitHub repository, and serves two things on the local machine:
   - **A dashboard** to query the data and change it and see what comes back and how long each step took: current
     values, values at an earlier point in time, a person's history, a save and its receipt, the change feed,
     Publish, erasure, a native query.
   - **A local API** that local agents can call to do the same things, with a machine-readable description.

Sam's words on the playground: "v0.1 will also come with a "demo playground dashboard" which should be able to load a
bunch of test data we store as a blob or w/e in github and then the dashboard helps you query and try to change things
and etc to play around with it and see times and return records and etc. Also it should expose APIs on a local server
that lets your local agents call the local server to query and etc".

Version 0.1 is finished when the scorecard has run on the merged branch at both ages, every failing line has a
written cause and a next step, and the playground starts from a clean clone with one command. It does not require
every scorecard line to pass.

## What is deferred past version 0.1

- Aging beyond 1 billion records (8 billion and more when there is budget for it).
- A bar for how fast notifications are sent, and a bar for the background writing after Publish.
- Moving every account to a successor database.
- Production key custody and rotation for erasure.
- Any work that needs cloud budget beyond the current $200.

## Budget

The cloud budget stays at $200. Server time goes first to the three measurements version 0.1 cannot be judged
without: the per-person writer against the grouped writer on ten accounts in one database, the scorecard on the
merged branch, and the 1 billion record rung.
